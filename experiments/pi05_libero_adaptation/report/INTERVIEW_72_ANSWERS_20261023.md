1. **主要对照是 E1→E2**：同一 LoRA 配方，额外冻结视觉。不是全量微调→纯 LoRA 的单因素比较。

## 第一组：项目定位与个人贡献

### Q01｜两分钟介绍：问题、判断、改动、结果

“我的问题是：强预训练 VLA 在特定任务域微调时，是否必须更新视觉大模块，才能保持闭环任务效果。我先审计了 π0.5 LoRA 配方，发现它并非只训练 adapter，还更新了约 4.148 亿视觉参数。于是以 E1 为参考，构造只额外冻结视觉的 E2，统一数据、更新预算和测评清单。

E1/E2 的可训练参数从 466,957,072 降到 52,153,376；同物理卡短测显存峰值低 24.54%、步时低 12.90%。冻结后确认集四套等权成功率少 0.50pp，配对 95% 区间为 [−1.85,+0.83]pp，满足预先登记的 −5pp 工程非劣标准。Long 局部有退化，单训练 seed 和跨进程复现波动仍是限制。

我最希望面试官记住的是**可审计的训练成本—性能取舍**，而不是已经证明视觉与动作模块的普适能力分工。”

### Q02｜四组分别回答什么？哪个结果意外？

E0 是全量适配参考；E1 是本地双分支 LoRA+完整视觉参考；E2 检验在 E1 上冻结视觉的收益；E3 检验非 LoRA、完整动作侧更新的实用配方。不是四组组成严格正交的完整因子实验。

可以解释一般预期“减少更新范围可能降低成本，也可能损失效果”，但**没有留档的事前完整排序不能补写成预登记预测**。结果中值得重视的是：E2 开发总体持平但套件变化相反；E3 虽训练约 430M、单步更快，开发仅 68.25%。这反驳“训练参数多或动作侧更新多就自然更好”的直觉，不证明其原因只有模块位置。

### Q03｜“原配置”到底是什么版本？

面试时说清：E0 是本地 `pi05_libero` 配方，E1 是自行添加的 `pi05_libero_lora`，E2 是 `pi05_libero_lora_frozen_vision`，E3 是 `pi05_libero_action_only`；共同加载 `pi05_base`，不是把官方 LIBERO 专家当成某组起点。

历史 `manifests/runs.json` 中 `code_commit=null`，当时未记录有效 Git commit，不能现在编一个 SHA。已有训练前/后关键源码内容哈希和候选冻结中的源码、权重、资产清单，能固定内容，但不能等同于完整干净 Git 历史。E1 所谓“原配置”应写作**本地参考配方**，不要写成“官方默认 π0.5 LoRA”。

### Q04｜个人贡献与真实修改函数

应按真实分工回答：“使用官方模型/训练实现和公开转换数据，在工具辅助下完成适配配置、参数审计、运行调度、身份化测评、成本记录和失败审阅。”公开数据转换不是本项目本人原创；不能凭产物宣称所有代码独立编写。

### Q05｜不只是打开一个冻结开关，价值在哪里？

开关本身很简单。判断力在于发现“LoRA”名字与实际更新范围不一致，然后用逐叶审计、smoke 差分、同预算闭环比较和成本测量闭合证据链。还要发现平均值相近却 Long 局部退化，并限制结论强度。

最核心的判断是**把更新范围审计变成可验证的 E1/E2 对照**；看门狗、哈希与统计是使该判断可交付的工程工作，不应夸大成全新学习算法。

### Q06｜讲一个真实排错过程

成本短测训练已跑完，但汇总断言失败。先区分“模型没有训练”与“观测没有记录”：checkpoint 和离线 W&B 仍包含完整 step，排除了训练未完成这一方向。检查 hook 生命周期后发现初始化重绑，修正安装时机；从原始 `.wandb` 恢复 E1 的全部 220 步指标，保留来源 SHA，不编造缺失的 monotonic 计时。

另一个真实故障是 E3 被外部任务显存扩张影响，两次保护性停止，后从 finalized `18000` 恢复。它是资源冲突，不是观察到 NaN 后修好算法。更近期发现的跨进程推理差异仍未定位，不能拿未解决问题作“完美解决案例”。

### Q07｜每个简历数字能否追溯？

### Q08｜证明到什么程度？

最有把握：在该 LIBERO 数据、seed42、30k 更新及固定执行协议下，E2 比 E1 显著减少可训练参数，短测成本较低，确认环境指标通过预设工程非劣门槛。

## 第二组：模型与训练机制

### Q09｜实际数据流与各组更新范围

实际路径可紧凑写为：`双相机RGB → SigLIP图像tokens；指令 → tokenizer/词嵌入 → 视觉语言前缀；带噪动作+时间条件 → action expert读取前缀 → 32维动作速度 → 10步积分采样 → 取前7维 → 每次执行5步再观察`。

客户端有 state8，但本实验 `pi05=True, discrete_state_input=False`：没有 π0 的连续 state token，也没有把 state 编入语言。不能画出不存在的有效 state 分支。

E0 全量；E1 视觉完整更新、语言/动作原大权重冻结且 LoRA 更新、投影更新；E2 再冻结视觉；E3 视觉/语言冻结、动作大权重与投影更新。不是各层分别训练再拼接的高层规划器。

### Q10｜视觉编码器冻结边界

视觉编码器产生图像表征，语言骨干在前缀中联合处理图像和指令，动作 expert 利用上下文建模动作速度场。E2 冻结匹配 `PaliGemma/img/.*` 的整个子树，包含其图像特征与该子树内输出映射，不只是 ViT 的部分 attention。

视觉语言交互在 `PaliGemma/llm` 内，**不属于这个额外 img 冻结规则**。E2 的语言/动作 LoRA 仍更新。确切边界以参数路径为准，差集恰为 23 个视觉叶、414,803,696 参数。

### Q11｜π0.5 相比 π0 的实际区别

π0 路径有 `state_proj` 连续 state token，时间嵌入与动作特征拼接后经过 MLP。π0.5 路径把时间经 `time_mlp_in/out` 作为 adaRMS 条件；其 state 可以通过 `discrete_state_input` 进入语言，但本实验显式关闭。

控制字段是 `Pi0Config.pi05` 和 `discrete_state_input`。四组都保持上述状态/时间设置相同；没有复现论文全部预训练配方，也没有把知识隔离研究的新变体自动等同于当前本地代码。

### Q12｜前缀与动作的注意力方向

当前前缀内部允许双向读取，前缀不能读后面的动作；动作 suffix 可以读前缀，并在动作块内部双向交互。不是每个动作 token 必须逐个自回归生成；mask 还屏蔽不存在相机的 padding。

训练一次联合前向预测整个动作块速度；推理可先计算/缓存前缀 KV，再在多次 flow step 中更新动作，不必每次重新编码完整前缀。方向性 mask 是信息读取限制，**不是自动的梯度 stop-gradient**。

### Q13｜flow matching 目标和积分方向

采用 `x_t=(1−t)a+tε`，因此目标 `u_t=∂x_t/∂t=ε−a`，训练 MSE `E[||vθ(x_t,t,o)−(ε−a)||²]`。本地代码确为此约定，t 从缩放后的 Beta(1.5,1) 采样，范围约 (0.001,1)。

推理从 t=1 的高斯噪声出发，向 t=0 积分，`dt=−1/num_steps`；Euler 更新 `x←x+dt·vθ`。符号不能反过来。动作维先平均，再对时间/batch 平均；25 维动作 padding 也进入当前原始目标。

### Q14｜预测10步，执行5步

一次返回10步动作，客户端排入前5步，然后重新取得观测再请求模型；flow 数值采样也是10次，但**10次积分和10步动作是两个不同概念**。

执行块长增加通常能降低模型调用频率，却增加开环误差和接触阶段反应延迟；减少块长会增加计算/服务开销。5 是本项目固定协议，不是通过系统搜索证明的最优值；20Hz 仿真下5个控制步名义约0.25秒，不等于含同步推理等待的真实机器人wall-clock频率。

### Q15｜用了哪些损失？是否真的做了知识隔离？

本轮下游微调只用动作 flow MSE，没有另外加入语言 CE、高层计划监督或本项目实现的联合预训练损失。公开基座此前如何训练与本轮优化目标不能混为一谈。

本地 `pi0.py/gemma.py` 这条路径没有显式把 action loss 对前缀表征做 `stop_gradient`。冻结来自优化/求导参数过滤，不等于实现了论文知识隔离。[作者 KI 说明](https://www.pi.website/research/knowledge_insulation)讨论的是另一训练设计；不能因模型叫 π0.5 就声称本轮复现了其全部梯度阻断机制。

### Q16｜冻结后梯度流向哪里？

E2 的可优化目标仍经动作 expert 和注意力连接影响语言/动作 LoRA 与投影；视觉权重不被选入求导与更新集合。视觉前向仍必须为输入提供特征，冻结不会让模型不看图。

若冻结层在可训练层之间，为计算上游梯度仍可能需要对它的输入求导，不能把整个计算块随意 no-grad。视觉位于最前端时有机会省下其参数梯度/部分反向与激活，但具体省多少依赖编译、remat 和图结构，需要实测。

## 第三组：数据与任务

### Q17｜四套任务和真实例子

Spatial 重点区分空间关系：如抓取“盘子旁的黑碗”放到盘子，不能抓另一个相似碗；Object 改变目标物体：如把 alphabet soup 放篮子；Goal 在同类场景中改变目标行为：如开中间抽屉；Long 是多阶段组合：如把黄白杯放微波炉并关门。

成功由 BDDL/环境谓词定义，不是看视频觉得“差不多放进去”；Long 需要组合目标满足，不是完成第一个子任务就计整轮成功。这些任务域在训练中已出现，不应自动称未见物体泛化。

### Q18｜为什么是1693条？清洗了什么？

1693 是下载的数据版本自带的轨迹数，不是我本轮自行清洗得到。来源链是公开 LIBERO 遥操作 → OpenVLA modified RLDS → Physical Intelligence LeRobot 转换，数据卡能核实最后一层。[数据卡](https://huggingface.co/datasets/physical-intelligence/libero/blob/main/README.md)。

常见“40×50=2000”只是原始名义数量。虽然2000−1693=307，但我没有逐步过滤日志，**不能声称亲自删除307条坏轨迹，或给每一步编造过滤数**。如追问完整 lineage，需补上游处理脚本/版本与条目映射；当前能准确交付的是所用版本及本地实际数量。

### Q19｜各任务数量、轨迹长度和采样权重

本次重读元信息：每任务29–50条。最少是训练 task_index6“把两只 moka pot 放灶台”，29条；最多 task16“开灶台”和29“巧克力布丁入篮”，各50条。全局轨迹长75–505帧，均值161.53、中位140帧。全部40项见附录A。

训练对合并 dataset 的帧/窗口锚点 shuffle，不是先均匀选task、再均匀选episode。长轨迹、帧数多的任务贡献更多样本。评测套件等权不意味着训练采样任务均衡。

### Q20｜样本和尾部 padding 是否计损失？

一个锚点输入当前双相机图像与语言，监督包含从当前帧开始的10个动作，动作7维再填充到32维。不是输入整段轨迹，也不是10张历史图。

本地 LeRobot `_get_query_indices()` 将越界未来索引 clamp 到本 episode 末帧，生成 `actions_is_pad` 等标记；但 repack/模型训练路径没有把该标记用作时间 loss mask。因此**尾部重复动作也参加损失**，不会跨 episode 取下一条轨迹。另有25维零 padding 也参与维度平均；这两种 padding 不同。

### Q21｜图像处理和语言左右关系

原始双路RGB为256×256，映射成 base/wrist；resize-with-pad 到224×224，并转换为模型所需的[−1,1]。仿真原始图像按 `[::-1,::-1]` 旋转180°来对齐示范；不是把已处理示范再翻一次，也不是BGR和RGB任意混用。

训练对非wrist做约95%随机裁剪、恢复尺寸和±5°旋转，双路加颜色扰动；没有随机水平镜像。避免镜像是重要的语言空间语义边界，但裁剪/旋转也可能影响可见性，不能宣称增强对所有指令绝对无影响。当前有代码路径和样本图检查，不应说旧6400条都保存了原始无损模型输入并逐字节验证。

### Q22｜动作、状态和维度

环境动作7维为末端控制的平移/旋转控制量及夹爪，不是7个关节角；旋转控制通道对应轴角型控制接口。state8由末端位置3、四元数转轴角3、两指关节位置2组成；state存在于接口但本配置不用于模型状态token。

本项目安装的 PandaGripper 中+1闭合、−1张开，已按实际控制器核对；不能套用别的机器人正负号。模型输出32维，反归一化后只取前7维，后25维是统一维度的填充，不代表32自由度机器人。

### Q23｜归一化从哪来？

使用合并 LIBERO 数据资产中的统一 `norm_stats.json`，π0.5 数据配置选择分位数归一化，主要依据q01/q99将数值映射到约[−1,1]，不是每task另算或用评测数据统计。统计文件也含均值等字段，不意味着实际采用z-score。

四组配置共享同源资产；审阅记录核验 E0/E1/E2 最终资产哈希相同，为 `c0ee3c1a6ca5f1414d31180af3bc333dca1d78cf912f341943191b393fe68707`。推理从checkpoint资产加载对应统计；配置名改变时显式指定assets路径，避免找错/漏加载。不要为补论述假称本轮重新全量计算过统计。

### Q24｜训练、验证和评测究竟如何划分？

数据元信息是 train=0:1693，没有本项目另建的轨迹级验证集。开发/确认指仿真评测的初始状态划分：Spatial/Long 0–19开发、20–49确认，Object/Goal 0–49确认。

没有训练/验证帧拆分，不存在可以宣称已证明的“验证轨迹无相邻帧泄漏”结论；模型训练见过全部40任务。这里主要是相同任务域内的固定环境状态评估，而不是排除布局重合后的未见任务/OOD验证；旧状态整体也已经暴露。

### Q26｜哪些用LoRA，为什么仍467M？

语言与动作expert的attention/FFN使用低秩增量，相关原始骨干权重冻结；图像编码器E1全量更新，动作输入/输出和时间MLP投影也全量更新。467M中414.8M来自视觉，所以不是纯adapter训练。

E2的改变不是把图像模块也改成LoRA，而是将它完全冻结。准确名称应为“双分支LoRA+投影，视觉可训练/冻结两配方”，简称时保留范围说明。

### Q27｜LoRA公式、初始化和真实层算例

按行向量约定，`y=xW+s·xAB`，W为d_in×d_out，A为d_in×r，B为r×d_out；新增参数r(d_in+d_out)，不含原有W。attention的Einsum实现默认s=alpha/r；本地rslora=False。语言r=16、alpha16，动作r=32、alpha32。

实际语言FFN输出线性为16384→2048，r16：每层新增16×(16384+2048)=294,912；18层为5,308,416。CSV中A形状18×16384×16、B形状18×16×2048，注意scan层轴不能漏乘。

本地A/B均用N(0,0.01²)初始化，并非B全零，因此初始LoRA增量不是严格零。FFN `_dot` 直接加低秩输出，未显式乘scaling；当前配置attention的alpha/r=1，与该FFN数值尺度相容，但不能假设未来改alpha时两类算子都会同样响应。这是实现细节，不是已验证的调参收益。

### Q28｜插入Q/K/V/O还是只插Q/V？

实际配置为GQA：Q走 `q_einsum`，K/V合在 `kv_einsum`，输出走 `attn_vec_einsum`；这些Einsum都接LoRA。FFN的两个gating分支和输出linear也接LoRA。不是只插Q/V。

语言r16、动作r32是所用模型变体的默认设置，本项目没有做rank选择对照。其他非当前分支可出现融合QKV，不能将源码里“有qkv分支”误认为本配置一定使用该分支。

### Q29｜52.15M全是LoRA吗？

不是。49,987,584是两分支LoRA，2,165,792是 `action_in_proj/action_out_proj/time_mlp_in/time_mlp_out` 的权重/偏置。原始llm子树内偏置、条件归一化等非LoRA参数被E1/E2冻结规则覆盖，不能笼统说所有LayerNorm也在训练。

简称LoRA是指核心参数化，不是严格的更新白名单。回答时给出上述账本，避免“只更新了52M adapter”的误解。

### Q30｜冻结过滤器返回什么集合？

`get_freeze_filter()`返回**冻结集合**；训练集合为 `nnx.All(nnx.Param, nnx.Not(freeze_filter))`。E1通过模型变体匹配llm中原有参数、排除LoRA叶，使增量可更新，但规则没有自动包含img。

E2增加 `nnx.Any(E1冻结规则, PathRegex('PaliGemma/img/.*'))`，取冻结集合并集。用CSV导出的训练路径集合做差，并实际比较smoke前后权重，能发现漏冻/误冻；只读注释不能完成验证。

### Q31｜如何证明真的冻住？eval等价吗？

静态核对trainable路径；训练中 `nnx.DiffState`只对训练集合求导，优化器只接收筛出的params，更新后再合并模型；独立10步smoke检查冻结叶零变化、训练叶变化并重载。E2记录23视觉叶与20其他冻结叶不变，20个LoRA叶和8个投影叶更新。

`eval()/train=False`控制增强/dropout等行为，不决定参数能否更新。有历史动量时，仅把梯度设零未必阻止AdamW/状态继续改变；必须从优化器更新集合排除，并验证差分。本项目E2从base建新训练，不是沿用E1动量状态后改开关。

### Q32｜动作专家组的严格范围和参数更多为何更差

E3白名单包括 `PaliGemma/llm/.*_1/.*` 的非LoRA动作分支，以及上述四个动作/时间投影；视觉、语言冻结。trainable430,098,464；smoke32冻结叶不变、19训练叶更新。

参数多但位置、预训练表征可适配范围、参数化和优化配方不同，不能由数量推断效果。E3开发68.25%只证明该配方在此预算下差，未排除学习率、收敛速度、恢复数据顺序等解释。

### Q34｜如何证明E1/E2只改视觉冻结

模型变体、数据和资产、LR/AdamW、batch32、30k、seed42、EMA关闭、最终checkpoint规则相同；训练参数集合差恰是23个img叶，已有自动审计和smoke。无额外梯度累积，计算BF16、受训参数FP32的管理策略一致。

### Q35｜基础checkpoint是否一致

四组都加载pi05_base的参数来源，E3是同来源的本地缓存，不加载E1/E2的LIBERO权重。LoRA结构增加了随机初始化的增量，所以“同预训练基座”不等于四组完整初始参数树严格相同。

不能证明预训练基座完全未接触相关任务/数据；贡献是下游适配成本对照，不把强预训练能力或可能的数据暴露解释成原创训练收益。

### Q36｜学习率相同就公平吗？

不一定。固定LR比较的是统一配方下的更新范围差异；给每个方法合理且对称的搜索预算，比较的是各自调优后的表现。两类问题应分开报告，不能一边细调一边保持默认。

本项目E1/E2同LR以隔离冻结；E0/E3用另一LR，故跨组不能只归因更新范围。没有对每个方法做充分调优，不能称已找到各方法最优性能。

### Q37｜预算按什么对齐？

本轮主要按batch32、30k更新对齐，约96万次锚点曝光；数据相同但不代表所有窗口独立或出现次数完全一致。相同时间则回答单位资源下效果，较快E2可以做更多更新，属于另一个实验。

没有做等GPU小时训练，也没有证据说明E2多训一定追平或超过E1。必须同时记录训练与闭环表现，不能凭每步更快推断到达同等性能的时间。

### Q38｜训练seed和评测seed各几个？

每种正式训练只做seed42。训练seed控制初始化、shuffle和训练随机量；评测按manifest为每个状态固定独立环境seed及策略噪声seed，服务使用显式高斯噪声。

很多评测seed只是在测同一个学到的模型，不能当作很多训练seed。已有固定输入跨新进程动作小量差异，说明控制seed也没有覆盖编译/执行的全部变异来源。

### Q39｜checkpoint怎么选？

固定最终29999，不是从确认集挑成功率最高者；step29900只是最后一个常规指标日志，不是把它当最终checkpoint。E0导出EMA，E1/E2/E3非EMA，按真实配方记录。

反复在同一测评状态上挑模型会带来选择偏差。若需要调checkpoint，应在开发集完成选择，再冻结候选后测确认；目前基准整体已暴露，不能假装全新测试。

### Q40｜E0是否更好？E3真的收敛了吗？

E0完整95.70%，E1 96.40%，E2 95.90%；确认E1−E0区间跨0，不能声称E1显著优于E0。简历强调E1/E2是因为它是更干净的冻结对照，不是隐藏E0；完整报告必须有E0。

E3 loss总体下降，29900为.0211，但没有足够长训练/调优或验证曲线证明充分收敛。结论是固定30k配方未通过开发筛选，不是动作侧训练永远不行。

## 第六组：闭环测评与计数核对

### Q41｜一个episode完整过程

持续从执行后的环境取新观测；环境成功即停止并计成功，否则到suite步数上限计失败。Spatial/Object/Goal/Long上限220/280/300/520。记录原始动作、边界标记、推理耗时、身份与失败视频；服务连接失败等另留attempt，不假装任务完成。

### Q60｜参数少88.8%，为什么只省24.5%显存？

总权重、语言/动作激活、缓存、工作区和运行时仍存在。粗略账：视觉N=414,803,696；受训FP32权重4B+梯度4B+Adam两状态8B≈16B/参数，冻结BF16权重2B，净省约14N字节≈5.41GiB；若冻结权重保持FP32，净省约12N≈4.64GiB。

实测省约8.00GiB，还可能包括视觉反向/激活、remat与编译临时内存等改变；运行时分配/采样也影响。没有分配级profiler不能把额外约2.59GiB精确归因。可训练参数比例与显存比例本就不是线性等价。

### Q61｜计时原始数字、预热、波动和同步

E1/E2平均3.927885/3.421316秒，每组独立220步，前20预热，200个相邻记录时间间隔统计。原生训练在 `jax.device_get` 读取指标后记录，避免仅测异步dispatch；三组统一用恢复的W&B前端wall-clock时间戳，不把E1缺失observer冒充monotonic记录。

本次从原恢复JSONL补算：E1中位3.927563、P95 3.931540、标准差.002157秒；E2中位3.420302、P95 3.427299、标准差.003513秒。这些只是**该前端时间序列**的描述，非GPU kernel延迟分布，也不含跨运行置信区间；数值很平滑不证明无共享干扰。

### Q62｜一步时间包含什么，快在哪？

相邻指标wall-clock间隔包含其间的batch获取/数据准备、训练前反向/优化器与同步日志等影响；不提供逐阶段百分比。初始化编译不在稳态200间隔内，最后一步之后的final checkpoint保存也不会凭“资源窗口覆盖保存”自动计入平均step时间。

冻结视觉理论上减少梯度/优化器及部分反向与重算，但没有CUDA事件/trace将12.9%拆到各阶段，不能声称视觉前向更快或数据读取完全未计时。需要profiler才能定位耗时瓶颈。

### Q63｜图像、batch、精度与梯度检查点是否相同

E1/E2成本短测同GPU1、新进程、batch32、224图像、双真实相机、horizon10、相同LoRA与计算/参数精度策略、同数据归一化和预分配关闭。没单独给E2打开另一种省显存模式。

本地Gemma使用 `nn.remat` 的nothing_saveable策略，SigLIP也有remat路径；两个配置共用同一实现，不能说“本项目完全没开梯度检查点”。实际计算图因冻结而改变，这恰是处理的一部分，但需把其他开关保持一致才可解释。

### Q64｜每步更快、训练总成本和推理收益

耗时下降 `(3.927885−3.421316)/3.927885≈12.90%`；同batch吞吐提升 `3.927885/3.421316−1≈14.81%`，不是同一个百分比。历史正式训练32.54/28.42小时，与短测方向一致但不等于独占测量。

没有多checkpoint成功率学习曲线，不能回答“达到同等成功率各需多少步”并编造加速比；同预算的训练成本有依据，time-to-target没有完成。推理都要经过视觉前向，参数没删，训练节省不能直接推出推理延迟、存储或实机控制更好。

## 第九组：解释、反证与下一步

### Q65｜是否证明不同任务对视觉更新的需求不同？

严格观察是：同一配置对照下，冻结视觉与套件成功率变化存在关联，Spatial更高、Long更低。将其解释为不同视觉适配需求是可能的，但未排除训练/执行波动、交互式LR需求、数据难度与优化路径。

E1/E2控制了相同LR与数据，但这不代表该LR对两者都最优，也不把单seed变成机制因果证明。合适措辞是“观察到异质性，提示需任务分层分析”，不是“揭示了模块能力分工”。

### Q66｜Spatial改善的可区分假设

假设A：全视觉更新过强，破坏预训练关系表征；预测在E1仅降低视觉LR或约束视觉漂移即可恢复Spatial，同时语言/动作LR不变。若不同视觉LR下都无一致趋势，解释被削弱。

假设B：小数据过拟合导致；预测独立轨迹/受控新布局验证中E1训练拟合更好却泛化更差，数据量增加后差距缩小。当前无该验证/规模曲线，所以不能说已经证实。假设C是seed/跨进程波动，多次重载/多seed会使增益不稳定；现有复现诊断使其不能忽略。单看“冻结像正则化”不能区分A/B/C。

### Q67｜Long下降是否一定视觉问题？看了多少失败？

不是。已审阅E1/E2开发40/46个固定失败，每视频5帧；E3 40/127，每视频8帧。E1/E2样本标签合计placement_contact20、pre_grasp9、stall_timeout2、uncertain9；E3为15/12/13的placement/pre_grasp/uncertain。没有全体确认失败逐帧复标。

关键帧可见抓取、放置和入口受阻，但没有足够盲法、首次偏离和风险暴露对照来声称“冻结后某机制失败显著增加”。新增24次探索重放及其中5个失败也有选样/复现限制，不是全体发生率。论文式结论需要目标定位、接触、阶段切换、超时等进一步可靠分型。

### Q68｜动作侧差能证明视觉必须更新吗？

不能，E2已经是在视觉完全冻结时获得高成功率的反例。E3还缺少语言LoRA适配，且参数化、LR/EMA等不同，不能用E3失败证明视觉必须训练。

应在相同视觉冻结条件下比较语言LoRA开/关、动作LoRA开/关，并控制起点、优化器与预算；再在相同语言/动作配方下改变视觉更新。这样才区分视觉编码与视觉语言交互路径，而不是凭名称“action-only”归因。

### Q69｜参数数量和位置怎么分离？

做近似匹配可训练参数预算的模块/adapter位置对照，例如调整rank使视觉、语言、动作适配各自预算接近；固定数据、训练/搜索预算和闭环协议，报告实际计数而不是名义rank。

参数量相近仍不保证优化难度、计算或表达能力相同；应结合模块干预、特征/行为探针与学习曲线。本项目没有这项匹配预算实验，因此E2 52M优于E3 430M只是数量不充分的现象证据，不是位置因果的完整证明。

### Q70｜只能增加三组，具体选什么？

以下是**备选设计，不已运行，也不因写入回答而自动启动**：

1. E1仅将视觉参数组LR缩至原来的0.1，其他组LR/数据/预算不变。若Spatial改善且Long保留，支持视觉过强适配假设；若不改善或总体恶化，不再单靠“过拟合/破坏表征”解释。
2. E2仅关闭语言分支LoRA更新，保留动作LoRA和投影。若明显下降，支持视觉冻结时仍需语言/融合适配；若接近E2，应放弃“语言LoRA是主要补偿来源”的断言。参数量变化是该干预的一部分，不能同时声称等参数预算。
3. E3只将LR schedule改成E2的warmup1k、2e−4→2e−5，其余保持E3。若大幅恢复，原动作侧低分很可能含优化配方影响；若不恢复，仍不能立即排除其他容量/数据顺序因素，但可削弱这一个LR解释。

三组不会自动解决单seed问题；关键比较仍应先约束推理复现并准备必要训练重复，而不是用三组结果直接宣布机制定论。

### Q71｜哪些条件容易失效？给两个测试

相机位姿/视角变化：冻结特征可能保留不适合新投影的偏置，更新视觉可能重新对齐。测试在保持任务/物体与控制器不变时，对相机施加分级位姿扰动，先零样本测鲁棒性，再用等量新视角示范适配；分别报告适配前后，不能混在一起。

物体外观/纹理变化：冻结可能有利于保留通用特征，也可能无法编码新的细粒度接触线索，方向不是先验必然。固定物体几何/任务与初始状态，仅改纹理/光照，比较逐任务退化曲线，再做同预算适配。若E2同样或更稳，必须承认“视觉更新对域移必需”被削弱。

### Q72｜接受质疑的哪部分，简历删什么？

接受：目前是指定数据/配方/预算的资源收益，成功率变化不足以证明模块能力分工。回应：不是只打开开关看截图；已有更新集合差分、smoke、同物理卡短测、固定清单配对测评、开发选择后冻结和条件性非劣检验，构成可核验工程结论。

若删最弱一句，删“揭示不同任务对视觉适配的需求规律/证明了视觉和动作的能力分工”。可保留为：“审计π0.5适配更新范围，并验证视觉冻结配方在固定LIBERO基准上降低训练成本、满足预设环境成功率工程非劣标准，同时披露Long局部退化与单seed限制。”
