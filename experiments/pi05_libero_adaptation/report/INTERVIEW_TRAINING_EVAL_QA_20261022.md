# π0.5 训练与测评：面试回答总结

整理日期：2026-10-22。用途：面试口述、技术追问与数据速查。基于本地 E0–E3 配置、参数审计、训练日志和冻结测评结果；外部 benchmark 定义与官方参考成绩另附一手来源。

边界：新增关键片段加权实验暂不开展；已有前置诊断仅提供局限与排查案例。本报告不新增训练或 rollout。以下“实测”是项目已经完成的工作；“原理/建议”不是伪装成已完成实验的结果。

## 0. 一分钟项目介绍

“我做的是基于 openpi 的 π0.5 参数高效任务适配，不是从零训练基础模型。数据是 LIBERO 四套共 40 个任务、1693 条示范、约 27.3 万帧。服务器有两张 RTX 6000D，每组实际单卡训练，batch 32、30k 更新。

我重点比较了语言和动作分支 LoRA，以及是否冻结视觉编码器。实际审计发现，E1 虽然叫 LoRA，但还更新完整视觉编码器，总共训练约 4.67 亿参数；E2 只额外冻结视觉，降到约 5215 万参数。

在冻结协议的确认测评中，E1/E2 四套等权环境成功率分别是 96.32% 和 95.82%。E2 相对 E1 的差值为 −0.50 个百分点，满足预先登记的 −5pp 工程非劣标准；采样显存峰值低约 24.5%，单步时间低约 12.9%。我的核心结论是训练成本与性能之间的取舍，而不是创造了新的 SOTA。同时保留了长任务局部退化、单训练 seed，以及跨进程重放波动的限制。”

## 2. 数据集怎么来的？自己采集了吗？

### 可以直接回答

“这轮没有自己遥操作采集数据，使用的是公开 LIBERO 示范数据。LIBERO 原始数据来自仿真人类遥操作；我实际训练的版本是 Physical Intelligence 发布的 LeRobot 格式，它由 OpenVLA 的 modified LIBERO RLDS 数据转换而来，合并了 Spatial、Object、Goal 和 Long 四套。”

这个来源链由 [LIBERO 官方仓库](https://github.com/Lifelong-Robot-Learning/LIBERO#datasets)和 [Physical Intelligence 数据卡](https://huggingface.co/datasets/physical-intelligence/libero/blob/main/README.md)支持。不要把原始任务名义上的示范数直接乘成“本地有 2000 条”，本地真实元信息是 **1693 条**。

接入时核对的内容包括：episode 边界、语言与 task 对应、双相机方向/尺寸、动作定义、padding、归一化统计和训练/推理变换一致性。LIBERO 动作已经是相对控制形式，π0.5 配方使用 `extra_delta_transform=False`，不能随意复制旧 π0 配方再做一遍 delta 变换。

训练集元信息全部是 train。本项目的开发/确认划分是**评测初始状态划分**，不是重新创建了未见任务的训练/验证集；不能把固定基准内测评说成未见任务或分布外泛化。

## 4. 参数、学习率、step、batch size 怎么设置？

### 可以直接回答

“我固定 batch 32、30k 更新，主要调的是更新范围，而不是做了一个很大的超参数搜索。E1/E2 共用同一 LoRA 配方，1000 步 warmup，峰值学习率 2e−4，余弦衰减到 2e−5；E0/E3 则用 10000 步 warmup 到 5e−5 的配方。E1/E2 是视觉冻结单因素对照，其他跨配方比较需要承认混杂。”

| 参数 | E0 | E1 / E2 | E3 |
|---|---|---|---|
| 起点 | `pi05_base` | 同一 `pi05_base` | 同一 `pi05_base`，不是从 E1/E2 接着训 |
| batch / updates | 32 / 30000 | 32 / 30000 | 32 / 30000 |
| warmup | 10000 | 1000 | 10000 |
| peak LR | 5e−5 | 2e−4 | 5e−5 |
| decay_steps / end LR | 1000000 / 5e−5 | 30000 / 2e−5 | 1000000 / 5e−5 |
| 优化器 | AdamW | AdamW | AdamW |
| 全局梯度裁剪阈值 | 1.0 | 1.0 | 1.0 |
| EMA | 0.999 | 关闭 | 关闭 |

本地 AdamW：β1=0.9、β2=0.95、eps=1e−8、weight_decay=1e−10，不要套用其他框架的默认 0.01。E0/E3 的 peak 和 end LR 相同，warmup 后并不是显著的余弦下降。

E1/E2 语言分支 LoRA 配置 rank=16、alpha=16；动作分支 rank=32、alpha=32，涉及 attention/FFN，不应简化为“只给 Q/V 加 LoRA”。具体缩放以本地算子实现为准。模型计算 dtype 为 BF16；受训参数按 FP32 管理，冻结参数按 BF16 管理，不能写成整个训练过程所有状态都是 BF16。

其他关键设置：action horizon=10、action_dim=32、语言最大长度=200；训练图像处理到 224×224；日志间隔 100 步，常规 checkpoint 间隔 1000 步，最后额外保存 `29999`。

### 为什么是 30k 和 batch 32？有没有别的尝试？

- 30k 参考了 openpi 的 LIBERO 微调配置，使预算明确；**没有证明 30k 是最优停止点**。
- batch 32 是本地单卡与并行资源条件下使用的实际值，所有主组一致。配置文件 E0 默认写 256，但正式命令覆盖为 32；看 argv 而不是只看默认配置。[官方配置入口](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/training/config.py)。
- 做过 E2/E3 独立 10 步 smoke 和各配方 220 步成本短测；这些是正确性/成本验证，不是调参胜负实验。
- 做过 E0–E3 更新范围/配方比较；**没有**完成同口径 batch 16/64/256、多个 rank、多个学习率或多个训练 seed 的正式网格搜索。
- 多任务 batch 32 是所有任务混合后的一批，不是每个任务各 32。

原理性经验：变大 batch 会改变梯度噪声、显存和数据曝光量，不能保持 step 不变后仍声称完全相同的数据预算。若用梯度累积，需要核对有效 batch 和 LR schedule；不能直接把学习率按 batch 倍数放大当作已验证结论。下一轮若调参，应一次只改主要因素、先短测再用开发 rollout 筛选；本轮不启动这些实验。

## 5. 多任务混合训练与单任务独立微调有什么差异，为什么？

### 可以直接回答

“我本轮实际做的是 40 个任务混合、通过语言区分任务的一套策略，没有做同预算的单任务模型对照，所以不能给出我自己实测的多任务提升百分比。一般来说，多任务共享抓取、定位和视觉表征，数据利用率与部署成本更好；但也可能有梯度冲突和长短任务采样失衡。单任务可以更专注，但数据少时容易过拟合，而且维护很多模型的成本更高。”

训练端使用整个合并数据集、shuffle 的窗口采样；没有额外实现每个 task 等概率抽样。因此较长或帧数更多的任务会贡献更多训练样本，不能称“40 个任务严格均衡训练”。评测端任务/套件等权不等于训练端任务均衡。

差异的机制属于原理，不是本项目因果实验：

1. 正迁移：抓取、避障、物体定位等可共享技能，稀疏任务从其他示范获得表征帮助。
2. 负迁移：相似图像对应不同语言目标或不同控制动作，可能出现梯度方向冲突、任务条件利用不足。
3. 数据不平衡：帧数多的任务/阶段主导 loss；低频精细操作未必有足够权重。
4. 单任务取舍：任务集中能降低条件区分难度，但可能牺牲通用性、灾难性遗忘和模型管理成本。

若设计公平对比，需要同时报告两种预算：一是固定总 GPU/更新预算，衡量工程成本；二是匹配每个任务的数据曝光量，衡量专门化收益。不能给每个单任务模型都训完整 30k，再和一组 40 任务共享 30k 比后忽略约 40 倍总成本差异。还需统一预训练起点、归一化、输入、评测状态和 seed，并逐任务看正/负迁移。

MetaWorld 的不同模型、不同任务集和接口结果，也不能拿来充当这项 LIBERO 多任务/单任务消融。

## 6. 训练目标是什么？主要看哪些指标和曲线？

### 可以直接回答

“这里是模仿学习的 flow matching，不是用在线奖励做 RL，也不是主要看语言 token 交叉熵。训练时对动作加噪，模型学习条件速度场，用预测速度和目标速度之间的 MSE 训练。训练健康看 loss、grad norm、LR、参数范数和资源；最终性能看闭环成功率和失败行为。”

对应本地实现：`x_t=t·noise+(1−t)·action`，目标速度 `u_t=noise−action`，优化 `mean((vθ−u_t)^2)`。时间与噪声每批重新采样，图像还有训练增强，因此 loss 本身存在随机波动。

已经记录的核心曲线：

- `loss`：看长期下降、平台、突跳以及与恢复时间的对应关系。
- `grad_norm`：记录的是 trainable 参数梯度的全局范数，源代码在裁剪前计算；观察到的日志又是区间平均，不能理解为每一步的裁剪后梯度。
- `param_norm`：源代码过滤后的 kernel 类参数范数，不是全模型所有参数的统一尺度，不能简单由大小判断某组更稳定。
- 步时、显存、日志心跳、checkpoint finalize：区分算法问题、I/O/编译等待、资源冲突。
- LR：本项目可由 schedule 和 step 重建；不应说日志已经完整记录了逐层梯度、裁剪比例、验证 loss 等所有诊断曲线。

建议但本轮没有连续完备记录的曲线：固定验证集 loss、逐任务/逐动作维 loss、梯度裁剪频次、各模块更新/参数比、多个 checkpoint 的同清单闭环成功率。**不能凭训练 loss 继续下降就声称没有过拟合。**

## 7. 实际观察到什么 loss 变化？有没有异常模式？

### 可以直接回答

“E1 的记录从 0.0940 降到 0.0171，E2 从 0.0936 降到 0.0162。总体是早期快速下降、后期缓慢下降，有局部抖动但没有持续发散。E1/E2 各 300 个日志点没有 NaN/Inf。这个结论只覆盖已有日志粒度，不代表我逐个原始 step 都检查了未记录的数值。”

| 日志 step | E1 loss | E2 loss |
|---|---:|---:|
| 0 | 0.0940 | 0.0936 |
| 1000 | 0.0337 | 0.0332 |
| 5000 | 0.0275 | 0.0254 |
| 10000 | 0.0243 | 0.0226 |
| 20000 | 0.0208 | 0.0192 |
| 29900 | 0.0171 | 0.0162 |

具体波动案例，而不是笼统说“很平稳”：

- E1 step 1600→1700：loss 0.0339→0.0377，grad norm 0.1450→0.1985；1900 时 loss 回到 0.0320。
- E2 step 2300→2400：loss 0.0290→0.0373，grad norm 0.1082→0.1933；2500 时回到 0.0285 / 0.0928。是短暂共同升高，没有演变为持续发散。
- 后 5000 步的已记录 loss：E1 均值 0.017532，标准差 0.000529；E2 均值 0.016518，标准差 0.000419。这是含下降趋势的日志点统计，不是固定 batch 下的纯梯度噪声估计。
- E3 step 29900 为 0.0211；从 18000 恢复后，18100 的日志 loss 与前一尝试不同。数据迭代器没有精确恢复，不能将此单独定性为模型突然发散。

重要日志口径：step 0 是单步；后续每个打印点主要是前一段约 100 步指标的均值，并非该单一 batch 的即时值。step 29900 不是最终 checkpoint `29999` 的完整验证 loss。

这些短暂波动的具体 batch 原因没有保存足够证据，不能断言一定是哪条坏数据或学习率引起。

另一个实际异常模式是“低 loss 不等于更好闭环”：E2 训练 loss 比 E1 略低，但完整环境成功率 E1 96.40%、E2 95.90%；E3 loss 仍能下降，开发成功率却只有 68.25%。平均监督误差与长序列误差累积不是同一个指标。

## 8. loss 震荡时怎么排查？

### 可以直接回答

“先判断是正常随机波动还是持续发散，不会一看到 loss 抖动就立刻减学习率。我会对齐 loss、梯度、LR、任务 batch 和资源日志；用固定 batch、固定 noise/time 做小规模复现。确认是数值或优化问题后再改学习率、warmup 或裁剪；如果是数据与接口错误，单纯降学习率治不了。”

可操作排查顺序（方法论，不是宣称每一步都已在主训练跑过）：

1. **核对测量。** 看原始值与滑动均值、日志平均窗口、恢复 step、是否混了不同尝试。不要只看 W&B 平滑后的图。
2. **看是否非有限。** 对输入、loss、梯度、更新、权重逐级查 NaN/Inf；保存异常 batch 与 checkpoint，停止覆盖现场。
3. **对齐优化阶段。** 看 LR warmup/峰值、梯度范数和更新比例；连续数百步恶化比单点波动更值得警惕。日志均值低于裁剪阈值不等于每一步都没触发裁剪。
4. **查数据。** 核对动作单位/顺序、夹爪符号、归一化、重复 delta、相机方向、时间对齐、episode 尾部 padding、任务采样比例和异常动作。
5. **固定随机量。** 对固定样本关闭增强，固定 flow time/noise 重复前向；必要时做极小数据过拟合 sanity check。注意这与完整闭环泛化是两件事。
6. **查冻结/恢复。** 确认预期 trainable 叶真的更新、冻结叶零变化，优化器状态与 global step 正确恢复，检查 EMA 与非 EMA 是否加载混用。
7. **再调参。** 确认是优化器动态后，才按单变量试验缩小 LR、延长 warmup 或调整有效 batch；FP32 对照用于定位精度问题，不默认推翻全部训练配方。
8. **最后回到行为。** 若 loss 正常而闭环差，按抓取、运输、放置、阶段切换看失败视频；优先查控制接口与数据分布，而不是只追求更低均值。

典型模式：持续 loss/grad 双增长可能是优化不稳；train loss 降而固定验证/rollout 恶化可能是过拟合或分布偏移；loss 近乎不动应查冻结错误、LR 和数据；周期性跳动应查任务/epoch/保存时序；loss 很低但动作不动应查 padding 稀释、常见动作占比和输入/反归一化。这里的“可能”都需要证据，不是由曲线形状直接诊断根因。

## 9. 训练中出现过不稳定或工程故障吗？怎么处理？

### 可以直接回答

“有遇到问题，但主要不能混为一谈：数值上 E1/E2 日志没有持续发散；资源上 E3 两次受外部任务抢占显存影响，被看门狗保护性终止；记录链路上还修过 W&B 指标 hook 被重新绑定覆盖的问题。我是先确认故障类型，再决定恢复训练还是修复记录，而不是一律重新训练。”

实际案例：

- **显存压力。** E3 自身占用约 33 GiB，但其他任务扩张导致整卡余量不足。看门狗按低于 4096 MiB 的保护阈值停止本项目，后续稳定空闲再准入；没有终止其他人的进程。保留 attempts，并从 finalized `18000` 恢复，最终完成 30k。
- **恢复局限。** 恢复模型、优化器和 step，不等于恢复数据迭代器的精确顺序。E3 这一点明确记录，不能说完全无缝、逐 bit 复现。E0 也存在早期重启/从 1000 恢复的历史，不包装成所有训练均一次跑通。
- **归一化资产。** 自定义配置名默认会寻找新的 assets 路径，复用数据时显式指定已有 `pi05_libero` 统计；否则可能找不到 norm stats。避免为了改配置名无意义重算或错用别的机器人统计。
- **记录 hook。** W&B 初始化重绑日志接口，使提前安装的 observer 失效；训练本身完成但成本汇总失败。修正挂接时机，从原始离线 W&B 记录恢复 E1 的 220 步指标，保存来源哈希，而不是编造缺失计时或覆盖旧记录。
- **预检。** E2/E3 正式训练前独立跑 10 步并比较参数：冻结叶不变、可训练叶有更新、checkpoint 能重载。不要把“配置写了 freeze”当作冻结成功。

还有一项属于**推理复现**而非训练发散：已完成诊断发现相同输入同进程重复一致，但跨新模型进程有约 0.003 量级动作差；底层来源未定位。特选 24 次历史分歧状态重放有 9 次成败变化，不能推广为全基准翻转率。不能把 seed 固定等同于绝对确定性，也不能说这项问题已经修好了。新增实验目前暂缓，不自动继续排查或训练。

## 10. 本地测评和官方结果一致吗？如何验证性能？

### 可以直接回答

“本地结果与官方 π0.5 LIBERO 结果处在相近水平，但不是严格对齐复现。官方仓库的四套平均是 96.85%，本地 E1 完整固定基准是 96.40%。我会同时报告各套件、样本数和协议差异，不只挑平均值，也不把不同 checkpoint、不同 batch 的结果当作同一实验。”

| 完整四套结果 | Spatial | Object | Goal | Long | 平均 |
|---|---:|---:|---:|---:|---:|
| 官方发布 π0.5 @30k checkpoint | 98.8% | 98.2% | 98.0% | 92.4% | 96.85% |
| 本地 E0 全量 | 97.2% | 98.4% | 95.8% | 91.4% | 95.70% |
| 本地 E1 | 94.4% | 99.2% | 98.4% | 93.6% | 96.40% |
| 本地 E2 | 98.0% | 98.2% | 97.4% | 90.0% | 95.90% |

官方行来自 [openpi LIBERO 结果说明](https://github.com/Physical-Intelligence/openpi/blob/main/examples/libero/README.md#results)，它是官方仓库参考结果，不是本项目提交榜单的成绩。本地 E0 是从 base 再微调的模型，不是“官方已发布 LIBERO checkpoint 在本地跑一遍”的完全同权重对照。

差异可能来自训练 batch/LR/EMA、checkpoint、图像/归一化、动作执行与 replan、超时、仿真依赖/控制器，以及数值/采样波动；未逐一消融，不能确定某一项解释了全部差距。官方数值接近只提供合理性参考，不替代公平本地 baseline。

### 本项目性能验证链路

1. **固定训练结果。** 各组使用最终 `29999`，记录配置、资产、权重类型；不根据确认结果挑最优 checkpoint。
2. **固定 episode 身份。** 每任务固定 init-state index/hash，独立环境 seed 和策略 seed；服务端接收显式高斯噪声，保证随机量可追踪，但不夸大为跨进程绝对数值确定。
3. **固定执行协议。** flow=10、horizon=10、每次执行前 5 个动作再重规划；settling=10。Spatial/Object/Goal/Long 最多分别为 220/280/300/520 个 policy steps。
4. **先开发后冻结。** Spatial/Long 各任务状态 0–19，共 400 次开发，筛选 E2、排除 E3；冻结候选和统计规则后，确认 Spatial/Long 20–49、Object/Goal 0–49，每组 1600 次。
5. **闭环而不是离线动作误差。** 环境一旦判成功即计环境成功，超时未达成计失败；基础设施异常单独留痕，不能通过重试失败任务刷分。
6. **配对统计。** 同状态比较，任务内成对 bootstrap，再按任务/套件等权。确认各套样本数不同，不能拿总成功数/1600 替代四套等权平均。
7. **保留审计。** E0/E1/E2 各完整 2000、E3 开发 400，共 6400 条；核验轨迹/失败视频 hash、动作形状、有限性与身份，保留失败视频。

确认主比较：E1 **96.3167%**、E2 **95.8167%**，E2−E1=**−0.50pp**，95% CI **[−1.85,+0.83]pp**。它通过预先登记的 −5pp 工程非劣标准，不等于证明二者完全相同、E2 更好，或误差只来自有限 rollout 抽样。

局限必须会回答：只训了 seed=42；已有任务/部分历史结果暴露；当前 bootstrap 不包含训练种子和跨进程重放波动；这些都没有被“6400 次有效记录”自动消除。

### 90%+ 的计分边界

这里的 90%+ 是**环境任务成功率**。另一个更严格的自定义指标要求任何原始动作不超出 [−1,1]；本轮该指标各组均为 0。已核验控制器裁剪运动输入、夹爪按符号执行，所以轻微原始输出超限仍可能完成任务。两种指标分开保留；不能把环境成功写成严格合规成功或实机安全性。

## 11. 为什么能做到 90%+？核心原因是你的改进吗？

### 可以直接回答

“90%+ 不能全部归功于我的方法。首先是强预训练 π0.5 基座，其次是同任务域的高质量示范微调，再加上训练/推理输入与动作接口对齐。LIBERO 是固定仿真任务和初始状态基准，不等于开放世界机器人能力。我的贡献主要是把更新范围做成可审计消融，并验证冻结视觉在明显降低训练成本的同时，维持了这轮基准上的高成功率。”

合理机制解释，不是逐项做过因果验证：

- 不是从 27 万帧里从零学视觉、语言和机器人控制；基座已经携带预训练能力。
- 任务域内监督提供目标物体、运动和阶段的动作示范；测试仍在相同四套任务域内。
- 第三人称与腕部图像提供互补视角，语言提供任务条件；但当前项目没有做去腕部/去语言消融，不能量化各自贡献。
- flow matching 生成动作块，滚动重规划从最新观测纠正轨迹；不是输出整条长轨迹后盲执行。相关提升也未做专门消融。
- 正确的图像方向、归一化、动作尺度、夹爪符号和环境成功判定，使模型学到的动作能在控制器里得到正确解释。

最有说服力的对照：E0 全量本来就有 95.70%；E1 96.40%、E2 95.90%，因此没有证据说“我的新训练结构把低成功率模型提升到了 96%”。E2 体现的是资源取舍；E3 开发 68.25% 是保留的负结果，说明在这套预算/配方下仅更新动作侧不足以维持原表现，但不能将根因单独归为缺少语言更新。

MetaWorld 上 π0.5 SFT 的历史五任务结果只有 29/100（v2）或 22/100（v3），不能说项目在所有平台均为 90%+；模型/任务/控制接口跨域后表现下降也提醒了这一边界。

## 12. 分层架构怎么训练？各层成功率是多少？

### 可以直接回答

“要区分‘网络模块分层’和‘高层规划—低层控制的层级策略’。我这轮是视觉编码器、语言骨干与动作 expert 的模块化 VLA，用动作 flow loss 联合适配或冻结不同模块；没有另训一个高层任务规划器，也没有独立训练抓取/放置技能路由器。因此我没有各层单独成功率，只有完整策略在不同任务套件上的成功率。”

### 当前实际训练路径

视觉编码器产生图像 tokens，语言骨干处理任务指令，动作 expert 在视觉/语言上下文和噪声时间条件下预测动作速度场。训练时通过同一个动作监督目标优化被允许更新的张量；没有另加本项目自研的视觉分类损失、规划 token 损失或层级奖励。

- E0：各模块全量更新。
- E1：完整视觉更新，语言/动作的原始大权重冻结，LoRA 和动作/时间投影更新。
- E2：再冻结视觉，保留两分支 LoRA 和投影。
- E3：冻结视觉/语言，更新动作分支大权重和投影。

冻结参数不代表所有冻结算子都无需参与梯度计算；LoRA 位于冻结骨干中间，梯度仍要经过相关计算。省下多少显存和步时必须实测，不由可训练参数比例直接换算。

若面试官口中的“各层”其实是任务难度/套件，给出完整结果：E1 Spatial/Object/Goal/Long 为 **94.4/99.2/98.4/93.6%**；E2 为 **98.0/98.2/97.4/90.0%**。这是四套任务，不是视觉层/语言层/动作层的成功率。

### 如果追问真正的层级系统怎么做（原理性设计，未实现）

高层将语言目标映射为子目标/技能序列，低层根据观测执行条件动作；可以先用示范切分/子目标标注分别监督，再在有明确评测与数据的前提下联合适配。需要分别测高层子目标可执行性、给定 oracle 子目标的低层成功率、阶段切换正确率，以及端到端完成率，并用 oracle-planner/oracle-executor 等对照定位瓶颈。

“整体成功率=每层成功率简单相乘”一般不成立，因为层间错误和状态分布相关。若只是粗略说明串联风险，必须明确独立性假设，不能用整体成绩反推出各层数字。

## 13. 怎么公平比较我的方法与 baseline？

### 可以直接回答

“我把方法目标定义为更低训练成本下维持任务表现，所以 baseline 不是只拿一个网上数字。E1 是本地参考，E2 只改变视觉冻结；固定数据、起点、更新预算、语言/动作 LoRA、优化器和闭环协议，同时报告性能、显存、步时、可训练参数及局部退化。”

最有依据的结论：

- E2 相对 E1：可训练参数 **−88.83%**、短测采样显存峰值 **−24.54%**、平均步时 **−12.90%**。
- 确认环境成功率差 **−0.50pp**，通过预设工程非劣边界，但不宣称效果更好。
- E2 确认 Long 相对 E1 **−3.67pp**，Long task 5/9 各 **−16.67pp**，Object task 5 **−10pp**，必须报，不用平均掩盖。
- E0/E1 还改变 LR/EMA/参数化；E3/E2 还改变参数化、更新范围和 LR，因此二者是配方比较，不是同等干净的单变量证据。

公平性检查：同起点/同数据版本与统计、同训练预算、同输入/相机、同 checkpoint 选择规则、同状态与噪声身份、同环境和动作适配、同超时/replan、同成功条件、同故障处理；然后看逐任务差、区间和资源开销。不把 baseline 用短超时、方法用长超时，也不只给新方法失败重试。

“我验证了训练成本优先的工程方案，但还没有完成多训练 seed、未见任务/实机、统一推理延迟与存储成本测试，也没有证明新算法普适优越。”这是合适的结论强度。

## 14. VLA 常用 benchmark 有哪些？各测什么？

### 可以直接回答

|---|---|---|
| LIBERO Spatial / Object / Goal / Long | 空间关系条件、物体变化、目标/行为变化、组合多步操作；也用于终身学习研究 | 逐任务/套件成功率；做终身学习还看迁移/遗忘。本项目只覆盖其中四套固定任务域，不自动代表未见物体或 OOD 泛化。[官方仓库](https://github.com/Lifelong-Robot-Learning/LIBERO) |

- 不说关键片段加权已经训练或已经带来提升；目前只有前置诊断，拓展暂缓。
