# 诊断测量补充与解释边界

本轮未改变已固定的 ±5 帧窗口、48 个示范样本、12 个 rollout 身份或模型权重。

- 示范关键帧人工审阅的标签是“抓取附近”“释放附近”“非搬运接触”“无法判断”，不是物理接触真值或 secure grasp 成功判定。每例查看第三人称和腕部的八个时刻，长于加权候选窗口的未来图像仅用于解释，不输入模型。
- 在查看响应统计前，额外定义了一个只读校准量：切换后夹爪两指绝对位置之和沿预期方向变化至少 2mm，并持续两个观测，视为可见指关节响应。报告 5/15 帧内响应及末尾截断分母。该量不证明抓持、释放后稳定或接触目标正确。
- E1/E2 离线损失用原始 checkpoint 保存精度、原训练数据预处理和归一化；eval 模式关闭图像增强。与日志中的 train=True 训练 loss 数值不直接对比。原动作 32 维 loss 中含 25 维填充，额外拆分仅作诊断，不改变未来主训练损失定义。
- 事件/非事件损失在 48 对同示范、运动量近似匹配的窗口上比较，每对共享 beta flow time 和高斯噪声，四次固定重复；配对模型使用同一组随机量。控制窗口仍可能在任务阶段/视觉难度上不同，不能由损失差推出加权的因果收益。
- 既有 rollout 的“每百步命令事件数”和覆盖率受轨迹长短及命令抖动影响，不等于首次失效处的事件发生率。只有标注了首次可观察偏离的时间区间，才能与事件窗口作时间关联；区间不确定时不强行归为窗口内。
- 源码中的 rollout 控制频率为 20 Hz，示范元信息为 10 Hz，MP4 播放帧率也是另一个量。视频比较统一标 policy step，原始动作与视频索引一一对应；±5 示范帧不能直接等同 ±5 rollout 步的物理时长。若报告事件距离，同时给原始 policy-step 距离，并使用 ±10 rollout 步作为 ±0.5 秒的时间对应参考，另列 ±5 步敏感性，不根据新结果调整。
- 重放发现历史成败存在变化，追加一个已暴露状态的构造种子、重复 reset 和固定输入三次推理检查；保存精确图像/状态/噪声。再做最多两个新进程重载推理，仍约束在原始 30 分钟短时 GPU 预算内。历史没有保存同一原始输入包，因而不能事后断言首步漂移的根因。
- 完成后的实测补充：同输入包在两个新模型进程中相对原当前服务的整段动作最大差为 0.003412/0.003613，各进程内部三次重复差为 0；两个新进程的首动作差为 0.001953。只证实跨进程数值差异，未确定编译/算子等底层根因。
- 全部 6 张配对重放接触表及 5 个当前失败的粗/细时间表已实际审阅。5 个标签保留 uncertain；两个停滞案例不指定伪精确首次失效点。区间最近事件距离同时保存最小/最大值，以及 ±5/±10 步的“可能覆盖”和“完整区间覆盖”，不强行二分，不计算选样偏置下的失败富集倍数。
