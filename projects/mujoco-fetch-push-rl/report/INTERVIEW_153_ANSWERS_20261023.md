## 第一组：项目价值、个人贡献与结论边界（1–17）

### 1. 用一分钟介绍项目：研究问题、方法、主要结果和局限分别是什么？不要从“我学了 CS285”开始。

我研究的是 MuJoCo FetchPush 中，固定交互预算下稀疏奖励的学习效果，以及策略对末端执行增益误差的敏感性。使用 SB3 的 PPO、SAC 和 HER，做五组、每组三个训练种子的对照，每模型约一百万步；用相同 100 个测试场景比较最后一步成功率。

最强结果是稀疏 SAC 加 HER 后成功率从 6.0% 提高到 98.7±1.2%，差 92.7 个百分点。每回合增益随机化没有提高两个范围外测试点的平均表现，保留了这个负结果。局限是弱基线诊断不充分、只有一个任务和三个训练种子；属于算法复现、实验控制与工程交付项目，不是新算法或实机机器人项目。证据：正式结果、配方。

### 2. 你的项目究竟验证了哪一个假设？这个假设在运行实验前写在哪里？

设计中的两个主要预期是：HER 能改善稀疏奖励学习；训练时随机化动作增益可能改善未知执行误差下的表现。五组对照、预算、种子、验证和五档增益在 `EXPERIMENT.md`、完整设计归档及正式 `protocol.json` 中有记录，冻结 runner 随正式任务保存。seed99 预实验达到准入门槛后才启动正式种子。

要注意：不能把“所有措辞都预注册过”说得太满。增益点的事前依据清楚；如果要证明某个汇总指标的等权定义也事先明确，仍要逐字对照原设计，而不能拿事后报告当证据。第117题专门说明这一点。

### 3. 请把项目结论拆成“数据直接支持的结论”和“目前只是解释假设的判断”。

数据直接支持：这套预算和配置下 C/D 差距很大；B 的三个种子明显分化；D/E 的范围外平均差为 −3.1667 个百分点；A 的三个种子在已有测试 CSV 中都与零动作最终距离一致。

“D 因闭环反馈已经足够鲁棒”“B 是探索不足”“E 因隐藏增益难以识别而失败”都是解释假设。现有末端轨迹、回放统计和内部诊断不足，不能把这些当作已经验证的根因。证据：本轮数据复核、正式结果。

### 4. HER 是已有方法。你复现它得到高成功率，新增的工程价值或分析价值体现在哪里？

价值在把公开方法落成可核验实验：明确变量和训练预算、隔离训练/验证/测试种子、保存完整模型及回放、检查恢复语义、按场景配对评估、输出种子统计和可回查的视频轨迹。还把增益随机化的负结果与弱基线风险保留下来。

这些体现工程与实验分析能力，不能包装成提出 HER、改进 SAC 核心或证明实机迁移。原包已含部分脚手架，新增贡献的来源还必须按第6题拆分。

### 5. 与直接运行 Stable-Baselines3 的官方示例相比，你增加了哪些必须由你负责正确性的部分？

需要负责增益包装是否只改变执行动作、`compute_reward` 是否兼容 HER、50 步截断是否保留、评估是否逐回合固定 seed、恢复时总预算是否正确、模型身份与统计是否一致。自动协调器还要拒绝不完整结果、避免误覆盖，并确认最终报告来自完整五组。

算法梯度实现由 SB3 提供，但接口接错仍会使实验无效。核对入口是 `run.py` 的 `ActionGain`、`assess`、`save_bundle/load_bundle`、`ExperimentCallback`，以及 `tools/complete_experiment.py`、`tools/summarize_results.py`。

### 6. 此前已有 AI 提供的训练脚手架。最终版本中，你亲自修改了哪些文件、函数和行为？为什么改？

可核实事实是：用户上传的原包已含 `run.py`、SAC/HER 接入和动作增益逻辑。`run.py` 相对原包的记录修改，是 `ActionGain.step()` 将标量奖励转为 Python `float`，满足 SB3 环境检查；批量 `compute_reward()` 仍返回数组。不能说这些原有功能都是自己从零写的。

后续补充了环境/恢复核验、实验协调、统计与报告、案例视频、官方 Zoo 复现材料，本轮又补充面试证据复核脚本。它们是在 AI 辅助下完成的工程材料；“亲自写过哪些”只能由你依据真实经历回答，文件存在不能替代个人参与证据。出处：原包修改说明及各工具源码。

### 7. 你最有把握现场重写的三个函数是什么？各自接收什么输入、输出什么结果？

优先练习：`ActionGain.step(action)`，输入4维动作，输出 Gymnasium 五元组；`assess(model, config, episodes, seed_base, gain)`，输入模型与场景设置，输出逐回合成功、距离和回报；分种子汇总函数，输入逐回合记录，先算每模型成功率，再算三个种子的均值和样本标准差。

这三类函数覆盖控制链、评估协议和统计口径。应能现场解释裁剪、终止/截断、最后成功与曾经成功、`ddof=1`；目前这是学习建议，不是已经通过现场考核的事实。

### 8. 项目里最难定位的一次实际问题是什么？你最初的判断、排查证据和最终根因分别是什么？

有明确根因的例子是环境检查报奖励类型不符合要求。原始环境返回 NumPy 标量，包装器直接透传；检查器要求 Python 标量。修复仅在 `step()` 出口使用 `float(reward)`，不改变奖励数值，也不把 HER 的批量奖励错误地转为一个 float。修改前后哈希及验收有记录。

另一次更严重的问题是 E 三个进程同时中断，但没有足够系统证据确定原因，不能说已经定位为 OOM。已归档旧输出并用相同参数从零重跑、缩短保存间隔。面试中应区分“已定位的软件问题”和“完成恢复但根因未知的运行事件”。

### 9. 哪个结果与你最初的预期相反？它改变了你对问题的什么理解？

最明确的是增益随机化 E 未提高范围外平均成功率：D 89.8±1.9%，E 86.7±8.5%。这说明增加扰动不自动带来更好的泛化，效果取决于扰动模型、训练预算与种子波动。

它促使我按增益方向和每个种子分析，而不是只展示一条均值曲线；不能进一步断言随机化普遍无效。证据：逐种子表与范围外复算。

### 10. 你为什么选择 FetchPush？任务中真正需要学习的困难是什么？

它提供标准化目标条件观测、连续动作和稀疏/密集奖励，适合控制变量地研究 HER。学习困难包括接近物体、形成有效推动、选对接近方向，以及在有限步数内把物体留在目标附近；接触动力学让“朝目标移动夹爪”不等于“把物体推到目标”。

环境已提供物体与夹爪状态，因此这里重点是策略学习和样本利用，不是视觉识别、标定或真实机械臂底层控制。

### 11. 如果用一个“先绕到物体后方，再朝目标推”的规则控制器就能完成任务，强化学习的价值体现在哪里？

规则控制器如果表现很好，会说明这个简化任务本身可被几何先验有效解决。RL 的价值应表述为在统一任务上检验数据驱动的学习机制、样本效率与控制误差表现，而不是证明“只有 RL 才能推物”。

若要主张 RL 在适应性或复杂接触中更好，需要加入规则基线并明确规则获得的状态和先验；现有项目没有这项证据。

### 12. 为什么没有把规则控制器作为基线？加入后，哪一种结果会削弱你对项目价值的判断？

当前设计范围是 A–E 算法与增益对照，为尽快完成完整实验，没有实现规则控制器。这是基线覆盖的局限，不能编造成“规则已被证明不行”。

若规则控制器在同样观测、50 步预算及增益条件下以更低工程成本达到相同或更高表现，会削弱使用 RL 解决这个具体任务的必要性，但不推翻 C/D 的实验对照。补充时应提前固定规则及调参预算。

### 13. 简历里“可复现代码”具体承诺了什么：能运行、统计结果接近，还是完全复现每一步？

首先承诺同版环境可启动、配置与模型身份可核查、评估与统计能从记录重建。重新训练希望观察相近趋势和种子分布，不能保证每个模型恰好得到同样成功率。

检查点恢复没有保存完整仿真与所有随机流，也不能承诺与不中断训练逐位一致。官方 Zoo 路线的回调和 seed 流还不同，主要参数相同不等于完全复刻旧数值。证据：官方入口手册、`load_bundle()`。

### 14. 简历里“独立评估”的“独立”具体指什么？评估程序独立、环境实例独立、种子独立，还是数据分布独立？

这里是最终模型保存后重新加载、使用单独环境实例、使用与验证不同的场景 seed 20000–20099，并且不按最终测试选模型。原正式评估仍复用 `run.py` 的环境和评估实现，不能声称由另一套独立实现交叉证明了所有结果。

训练和标称测试来自同一初态分布；分离 seed 不等于分布外。增益0.6/1.4是相对于 E 的训练增益区间而言的范围外条件。后补 API 评估器仅抽样核对旧结果。

### 15. 你能否指出一项自己尚未掌握、主要依赖库实现的关键机制？你如何控制它带来的风险？

可以坦诚说明没有独立重写 SAC 自动熵优化、HER 环形回放的回合索引管理，或 MuJoCo 接触求解。控制风险的方法是锁定版本、阅读关键路径、做接口和边界检查，再用小训练、恢复与模型加载验证集成行为。

不要以“库已经实现”为由跳过理解，也不要把能调用 API 当成已掌握全部优化细节。具体薄弱点需要你按自己的掌握程度选择。

### 16. 如果只能保留一个实验结果写简历，你保留哪一个？为什么它的证据最强？

保留 C/D：同样稀疏奖励、SAC 主体和交互预算，接入 HER 后从6.0%到98.7±1.2%，增加92.7个百分点。三个训练种子 D 都很高，比 B 只有一个成功种子的均值更稳。

同时注明这是固定配方下的结果，C 仍是很弱的基线；不把收益拆成已经验证的某个微观机制，也不写成与全面调参的最强 SAC 比较。

接受这个定位。可展示的是来源可追踪、明确对照、真实负结果、完整模型和逐回合记录、恢复机制及官方入口映射，而不是算法原创性。

## 第二组：机器人任务、状态、动作与奖励（18–34）

### 18. 写出这个任务的状态、观测、动作、转移、奖励和目标；哪些量策略实际能看到？

底层状态包含 MuJoCo 的关节位置/速度、物体位姿、接触及仿真内部状态；策略看到的是25维运动学观测、3维物体已达成目标、3维期望目标。动作是4维归一化末端平移与夹爪指令；动力学由环境控制处理和 MuJoCo 演化决定。

奖励由下一时刻物体位置与目标距离计算。目标是50步结束时距离小于0.05 m；“曾到达”是另存的辅助量。E 的真实状态还包含回合固定增益 g，但它没有直接进入策略输入。

### 19. `observation` 的 25 个元素分别是什么？请按实际顺序说明，而不是只说“位置和速度”。

按 `fetch_env.py::_get_obs()` 和 `generate_mujoco_observations()`，使用从0开始的索引：

| 索引 | 内容 |
|---|---|
| 0–2 | 夹爪末端世界坐标 xyz |
| 3–5 | 物体世界坐标 xyz |
| 6–8 | 物体相对夹爪位置 `object_pos-grip_pos` |
| 9–10 | 两指关节位置 |
| 11–13 | 物体旋转欧拉角 |
| 14–16 | 物体线速度减去夹爪线速度，再按控制步长缩放 |
| 17–19 | 物体角速度乘控制步长 |
| 20–22 | 夹爪线速度乘控制步长 |
| 23–24 | 两指关节速度乘控制步长 |

这些速度项已经乘 `dt=0.04 s`，不能再当成未缩放的 m/s 原值解释。Push 的两指被锁定，但观测仍保留对应维度。证据：本地 Robotics 1.4.0 源码；官方任务说明可辅助理解。

### 20. `achieved_goal`、`desired_goal` 与 `observation` 分别承担什么作用？有没有重复信息？

`observation` 描述运动学信息；`achieved_goal` 是物体当前位置；`desired_goal` 是要求到达的目标。物体位置确实与25维中的第3–5维重复，这是标准 GoalEnv 接口，便于通用目标重标记和奖励重算。

HER 改的是两侧观测的 `desired_goal`，不是把物体实际位置改掉。目标字段独立也要求25维里不要额外藏一份未同步更新的目标信息。

### 21. 字典观测进入 `MultiInputPolicy` 后，实际怎样组合成网络输入？总维度是多少？

默认 `CombinedExtractor` 对这些非图像 Box 字段分别展平后拼接，得到 `3+3+25=31` 维，没有自动去掉重复物体位置。本地 Dict 空间键顺序为 `achieved_goal`、`desired_goal`、`observation`，因此按此顺序拼接。

PPO 和 SAC 的 MultiInputPolicy 都接到这个31维特征；其后网络结构并不完全相同。实测维度与字段顺序见本轮运行时核验。

### 22. 机器人有几个关节自由度？为什么策略动作只有 4 维？这两个数字分别描述什么？

通常说 Fetch 是7自由度机械臂，指手臂七个关节。完整仿真模型还含基座滑动、躯干、头部、夹爪及物体自由关节，因此不能把整个 `model.nv` 直接当作手臂自由度。

策略的4维动作描述任务级控制接口：3维笛卡尔平移加1维夹爪。它不逐一给七个关节下指令。本轮实测完整模型 `nq=22`、`nv=21`、`njnt=16`，包括物体自由关节；其四元数占4个位置数但只有3个旋转自由度，故nq与nv不同。关节名也已保存，可现场区分“广义坐标数、速度自由度、关节个数”。

### 23. 第四维动作在 FetchPush 中是否产生实际控制效果？保留它会影响哪些学习过程？

FetchPush 设置 `block_gripper=True`，底层把夹爪控制置零并在回调中固定手指，因此第四维没有用于开合推物。它仍存在于策略输出、SAC 动作概率和目标熵计算、Q 输入以及 PPO 分布中。

无效维度可能浪费容量和探索，并影响熵正则的尺度；本项目没有做删维消融，所以不能量化其影响。默认 SAC 目标熵仍按4维算为−4。

### 24. 策略输出 `[1, 0, 0, 0]` 时，环境内部究竟修改什么量？它代表 1 米、1 米每秒，还是经过缩放的指令？

在 g=1 时，前三维先经包装器裁剪，然后环境将平移乘0.05，给 mocap 一个 x 方向0.05 m的目标增量；不是直接把物体移动1 m，也不是设定1 m/s。

这只是目标位置增量，实际末端运动还受约束和动力学影响。若 g=0.6，则对应名义目标增量0.03 m；高增益乘积超过1时先被裁剪，最大仍为0.05 m。

### 25. 请沿实际调用链说明：策略动作 → 增益包装 → 裁剪 → 环境动作处理 → MuJoCo 仿真。

SAC/PPO 产生动作 → SB3 根据动作空间做相应缩放或裁剪 → `ActionGain.step()` 复制动作、前三维乘 g 并裁到[-1,1] → Gymnasium `RobotEnv.step()` 再按空间裁剪 → Fetch `_set_action()` 将前三维乘0.05、指定固定姿态并屏蔽夹爪开合 → `ctrl_set_action/mocap_set_action` → MuJoCo 运行20个物理子步。

回放中存的是策略侧、增益处理前的动作，而物理世界执行的是增益变换后的动作；对固定包装环境这是对应的状态转移。E 的增益隐藏则引入第110题的部分可观测性。

### 26. 环境怎样实现末端位置控制？你是否读过它使用的 mocap 目标、约束或执行器代码？

本地 `mujoco_utils.mocap_set_action()` 先把 mocap 目标对齐到相应实际刚体位置，再叠加位置增量并设置姿态。机器人 gripper_link 与 mocap 存在 weld 等约束，MuJoCo 的约束求解驱动实际机械臂跟随目标。

这里不能声称项目自己实现了一个解析 IK 或关节 PD 控制器。需要沿 `fetch_env.py::_set_action`、`mujoco_utils.py::mocap_set_action/reset_mocap2body_xpos` 和 XML 的 weld 约束读实现。

### 27. 末端指令位置与末端实际位置一定一致吗？接触、约束和仿真动力学分别怎样影响它？

指令修改的是控制目标，实际末端由质量、惯性、约束求解、关节范围、碰撞和物体接触共同决定。接触时，即使目标继续向前，夹爪实际位移也可能受限，并向物体传递作用。

因此动作幅度、mocap 位移、夹爪位移和物体位移是四个不同量。现有案例记录了策略动作及末端、物体位置，但没有完整记录接触力，不能据此计算真实控制跟踪误差的全部来源。

### 28. 控制周期和物理仿真步长分别是多少？一次 `env.step()` 包含多少个物理子步？

本版 Push XML 的物理步长为0.002 s，`n_substeps=20`，一次环境控制步推进0.04 s，即25 Hz。运行时读取 `model.opt.timestep`、`env.unwrapped.n_substeps` 和 `dt` 已核对一致。

训练墙钟时间还含 Python、推理与梯度更新，不能用仿真时间推算实际耗时。接口及数值同时见本轮运行时核验。

### 29. 50 个控制步对应多长仿真时间？它怎样影响任务难度和动作增益实验？

`50×20×0.002=2 s` 仿真时间。预算短，策略必须迅速接近和推动；低增益会降低单位控制步的可达位移，因此固定50步的下降可能混入“来不及完成”的影响。

这不自动证明低增益下控制不稳定。区分时间预算和误差补偿需要延长步数等额外诊断，第108题给出方案。

### 30. 初始夹爪位置、物体位置、目标位置分别怎样采样？哪些固定，哪些随机？

每回合从环境保存的机器人初始状态恢复，夹爪起始位置基本固定。物体 xy 在初始夹爪 xy 周围±0.15 m内采样，并拒绝与夹爪平面距离小于0.1 m的样本；物体高度与初始姿态按环境设置。

目标在初始夹爪位置周围±0.15 m采样，再把 z 固定为物体桌面高度；Push 不采空中目标。它没有要求目标远离物体。依据：`_reset_sim()`、`_sample_goal()` 和 Push 构造参数。

### 31. 环境是否保证初始物体不在成功范围内？你怎么解释零动作策略也有 6% 成功率？

环境没有拒绝“物体已在目标阈值内”的初始化。在100个固定测试场景中，20002、20027、20043、20066、20073、20086这6个场景初始距离已小于0.05 m；零动作最后仍成功。

所以6%是这批场景的自然基线，不能理解成策略学会6%的有效推物。它不是环境通用常数，换一批100个场景未必仍为6%。证据：零动作 CSV 与本轮数据复核。

### 32. 写出密集奖励和稀疏奖励的公式，并解释奖励大小、单位与成功阈值之间的关系。

令 `d=||achieved_goal_next-desired_goal||₂`，阈值 ε=0.05 m。密集奖励 `r=-d`；稀疏奖励 `r=-1[d>ε]`，即阈值外−1、阈值内或相等为0。报告成功则按最后一步 `d<ε`。

密集奖励是以米计距离的负数；稀疏奖励为无量纲惩罚，不应把两种累计回报直接排大小。两者都不是“成功额外加1分”的实现。

### 33. 奖励函数与 `is_success` 在“距离恰好等于阈值”时，判断边界是否完全相同？你检查的是文档还是源码？

不完全相同：源码稀疏奖励用 `d>ε`，成功用 `d<ε`。恰好相等时奖励0，但 `is_success=0`。本轮批量探针用距离0、0.05、0.051，得到奖励0、0、−1和成功1、0、0。

依据是安装版本源码与运行时探针，不仅是文档概括。真实浮点距离接近边界时也要避免把显示四舍五入后的“0.050”当成精确相等。

### 34. 你把状态输入策略，但没有关节状态或历史观测时，凭什么认为这些信息足够完成控制？有哪些隐藏变量可能破坏这个假设？

位置、相对位置及速度给了闭环推物很强的信息，D 的高成功率说明它们在当前任务分布上足以学到有效策略；这不是对完整 Markov 性的证明。

未直接输入的关节构型、接触状态、求解器内部量以及 E 的增益都可能影响未来。若同一可见观测对应不同隐藏动力学，无记忆策略只能学折中映射；可用历史堆叠、递归策略或显式参数输入进一步诊断，但本项目没有做。

## 第三组：弱基线与行为诊断（35–51）

### 35. A 组三个种子都是 6%，最终距离也几乎相同。你怎样区分“算法没学会”与“训练、加载或动作执行有错误”？

已有证据包括环境检查通过、小训练确实更新、最终模型元数据达到预算、评估身份匹配，以及同一套入口的 D 能完成推物。这些降低了通用管道错误的可能性，但不能排除 A 特有配置或动作行为问题。

本轮从已有 CSV 确认 A 三个种子的逐回合最终物体距离都与零动作一致。下一步最有效的是比较夹爪轨迹、动作、接触/物体位移及加载前后参数；不能仅凭6%直接判定“PPO算法不行”。

### 36. 你检查过 A 组训练前后网络参数是否变化吗？策略输出、梯度范数和价值估计有什么变化？

正式实验没有保存初始网络快照，也没有记录梯度范数，所以不能声称已做正式训练前后逐参数比较。最终模型 `_n_updates=4890`，日志中有非零 KL、clip_fraction 和策略损失，说明确实运行过优化步骤，但不等于每个梯度都有效促进推物。

例如 A seed0 最后已记录 KL约0.01185、clip_fraction约0.148、value_loss约0.00109、explained_variance约0.99993。高解释方差只说明价值拟合当前回报，不能证明学到有效推动；正式策略全测试动作幅度尚未系统汇总。证据：运行时核验的最后日志摘录。

### 37. 报告只说明 A 的 seed 0 与零动作的逐回合最终距离一致。seed 1、seed 2 有没有做同样检查？

原诊断只写 A seed0；本轮新增了**只读事后复算**：把 A seed0/1/2 的已有100回合最终距离分别与同场景零动作 CSV 配对，三个种子的最大绝对差都为0。

这不是重跑了零动作，也不是记录了所有动作；新增结论只限于最终物体距离相同。证据在 `interview_evidence_20261023.json` 的 A 三条记录，原正式报告没有被改写成新增实验。

### 38. 最终物体距离一致，能不能推出策略输出的是零动作？机器人可能移动了却始终没有碰到物体吗？

不能。夹爪可能移动、升高、远离物体或擦碰但没有产生最终位置差异；即使末端动作非零，物体也可能始终未被有效推动。

而且仅一个标量距离相同，不严格等于三维物体轨迹相同。应记录策略动作、末端轨迹、物体轨迹和接触信息，才能区分“没动”和“动了但没推到”。

### 39. 你记录过末端轨迹、动作幅度、物体位移或实际接触信息吗？哪个指标最能区分“没动”和“动了但没推动”？

六个 D/E 案例有逐步策略动作、夹爪位置、物体位置、目标、奖励、距离及成功记录；没有保存全矩阵的末端轨迹，也没有接触力/接触对记录。因此不能把视频案例当成 A/C 的行为诊断证据。

最直接的区分是联合看末端路径长度与物体最大位移：末端明显移动但物体位移近零，支持“没有形成有效推动”；接触对/接触力则能进一步区分没接触和接触无效。

### 40. 为什么零动作基线直到正式实验结束后才加入？如果项目重做，你会把它放在哪一步？

这是前期验收遗漏。初期重点验证环境、HER、恢复和训练是否能运行，没有先校准任务初始化本身的成功率；正式结果出现6%平台后才补诊断。

重做应在正式训练前加入零动作、随机动作，条件允许再加简单几何规则控制器，并同时记录初始成功率和物体位移。这样可以提前知道“6%”的解释边界，而不是事后才发现。

| C | 0/94 | 0/94 | 0/94 |

D约97.87%、97.87%、100%；E约100%、97.87%、92.55%。这是事后描述，不替换正式98.7%口径，也不用于重选模型。

### 42. C 组也是 6%，但距离是 `0.193±0.018 m`，A 是 `0.182±0.000 m`。相同成功率是否掩盖了不同的行为？

是。成功率只按5 cm阈值二分，无法表示阈值外到底差6 cm还是30 cm。A 的距离与零动作一致，而 C 的平均最终距离更远、种子间有差别，表明即使都只有6%成功，也可能有不同物体行为。

这仍不能从距离直接重建动作或接触过程。应并列报告最终距离、初始到最终距离变化、物体位移和轨迹，而不是把6%的模型视为完全等价。

### 43. C 是否把一些物体推得更远，甚至破坏了原本已成功的场景？有哪些轨迹能证明或反驳？

本轮配对复算发现，C 的 seed0/1/2 分别有5/17/0个场景的最终距离，比零动作同场景大超过1 cm；因此至少有“最终离目标更远”的证据。它不是逐步轨迹，也不能证明每个过程都发生了主动反向推物。

对那6个初始已成功场景，C三个种子全部保持最后成功，现有记录反驳“C破坏了部分初始成功场景”这一具体猜测。不能为了回答问题而编造这种失败轨迹。

### 44. B 组的 53%/6%/6% 是什么分布特征？只报告 `21.7±27.1%` 会遗漏什么？

53%/6%/6%在这三个样本中表现为一个相对成功、两个停留自然基线；不能凭三个点拟合或证明总体双峰分布。均值21.7%、样本标准差27.1%容易让人误以为每次都能达到二成左右。

应展示三个原值及分种子学习曲线，说明复现稳定性差。也不能只挑53%写简历并忽略另外两个种子。

### 45. B 的两个失败种子与成功种子，从训练早期开始，哪些指标首先出现差异？

有逐种子 `progress.csv` 与 `validation.csv`，能检查 success、distance、actor/critic loss、ent_coef 等随步数变化；但本项目没有完成定义明确的“最早分叉点”分析，也没有早期动作、接触和回放组成记录。

答题时应说这是可进一步从日志分析的问题，不能编造“第几万步熵先塌缩”。建议按相同环境步对齐三种子，先找成功/距离分化，再检查此前的熵系数与critic loss，并回放对应保存点。

### 46. 你认为 B 的问题来自探索、价值估计、策略更新、奖励设计，还是实现？分别需要什么证据？

探索问题要看接近物体、接触和有效推动频次；价值问题要看 Q/TD误差与过估计；策略更新问题看动作分布、熵、饱和及更新幅度；奖励问题看接近目标与接触之间的激励关系；实现问题则检查加载身份、奖励、截断和回放接口。

现有结果不能在这些原因中定案。默认日志只覆盖一部分内部指标，缺少Q分布、TD误差分位数和全量轨迹；必须把“可疑机制”和“已测证据”分开。

### 47. 第 3 页里 B 的 seed 0 验证成功率曾到约 90%，最终测试却为 53%。怎样拆分训练后期退化与验证集、测试集差异？

本轮读取 B seed0 验证 CSV：94万步为90%，100万步为55%；最终100回合测试为53%。因此同一验证集上的后期下降有直接证据，55%与53%的差还混有20场景和100场景抽样及初态差异。

不能把90%→53%全归因于测试分布，也不能直接断言参数数值发散。若要更细拆分，应对多个保存点用同一独立诊断集配对评估；不得事后把最佳验证模型替换成原定最终模型而仍沿用旧结论。

### 48. D 的学习曲线在约 30 万步附近明显上升。这个转折与成功经验数量、有效推动比例或回放内容变化有关吗？

曲线能说明某段步数后成功率上升，不能证明恰好因为回放中成功经验到达某个比例。正式运行没有保存每时刻有效推动比例、真实/虚拟成功奖励组成和接触事件。

合理假设是探索得到更有用的转移后，HER可增加目标条件学习信号；要验证需要对齐回放统计、物体位移和训练曲线，再设计采样消融。当前只能把转折当成观察现象。

### 49. 当前数据支持“PPO 不适合 FetchPush”，还是只支持“这套 PPO 配置在这个预算下没有学会”？两种说法的证据要求差在哪里？

只支持“这套 PPO 配置在约100万交互步和当前任务分布下未学到有效推物”。证明 PPO 普遍不适合，需要更广的合理调参、网络与奖励设置、多个预算和种子，并排除实现及探索瓶颈。

没有这些证据就写“PPO不适合机器人任务”会过度外推。项目报告应保留任务、配置和预算限定。

### 50. 密集奖励 B 远弱于稀疏奖励＋HER 的 D。你怎样避免把这个结果简单解释成“稀疏奖励更好”？

B→D同时改变奖励形式和HER，不能只归因于稀疏奖励。要看B/C比较同SAC下奖励密度的变化，再看C/D比较稀疏条件下HER的变化。

当前B平均高于C，而D远高于C，因此最直接结论是本配置下HER大幅改善稀疏SAC。完整拆分奖励与HER交互还需要密集奖励+HER组，本项目没有。

### 51. 如果只能加一个最有诊断价值的实验，你会选更强的 PPO 配置、更长的 SAC 训练、规则控制器，还是轨迹诊断？为什么？

优先轨迹诊断：在固定场景记录 A/B/C 的动作、末端路径、物体位移与接触，先确认是未接近、未接触、推动方向错误还是到达后离开。它比直接加训练时长更能降低当前机制不确定性。

规则控制器可作为随后校准；调参和延长训练应在确定管道与行为无误后进行。这里是后续建议，本轮没有为回答面试题启动新训练。

## 第四组：SAC 的数学与实际实现（52–68）

### 52. SAC＝带熵正则的离策略演员—评论家算法。请写出本项目对应的优化目标，并解释熵项。

目标可写作 `J(π)=E[Σ γ^t(r_t+α H(π(·|o_t,g)))]`，实际训练使用 soft Bellman 目标与策略损失。这里 `g` 在公式中表示目标位置；为免与执行增益混淆，下面把目标写作 `z`、观测写作 `x=(o,z)`。

熵项鼓励策略保留随机性，在预期回报和探索之间权衡。连续动作使用微分熵，其数值可为负；高熵不是探索成功的充分条件，尤其第四维在Push中没有物理作用。项目使用 SAC 的 twin-Q 版本，没有另一个单独 V 网络。依据：本地 `sac/sac.py` 与策略源码。

### 53. “离策略”具体体现在哪一步？当前策略与采集回放样本的策略不同，为什么还可以训练？

SAC 从回放池采样旧行为策略采集的转移，当前策略参数可以已改变；Q学习在这些状态动作上拟合 Bellman 关系，下一动作由当前策略采样。HER 进一步改变目标，但保留真实转移。

这不要求像 PPO 那样只围绕最近一版行为策略更新，也不意味着任意旧数据都一定有效：覆盖不足、分布偏移、非平稳动力学仍可能造成问题。标准此版本并未给每条回放加行为策略重要性权重。

### 54. 写出目标 Q 值的计算公式，逐项说明下一状态、下一动作、目标网络、熵系数和终止标记。

本项目 SAC 的一阶目标为：

```text
a' ~ πθ(·|x')
y = r + γ(1-d_boot) [min(Q̄1(x',a'),Q̄2(x',a')) - α log πθ(a'|x')]
LQ = 1/2 Σ_i mean[(Qi(x,a)-y)^2]
```

`Q̄` 为目标critic，`d_boot`表示需要停止bootstrap的真正终止；时间截断会在回放采样时屏蔽，不应直接拿 Gymnasium 的 `terminated or truncated` 代替。HER 虚拟样本的 `x/x'` 使用同一新目标，`r`重算。代码位于 `sac.py::train`，不是手写训练器。

### 55. 为什么使用两个 Q 网络并取较小值？它缓解什么问题，又可能引入什么偏差？

策略优化倾向选择Q较高的动作，函数逼近误差可能被利用而产生过估计。两个相对独立的critic取最小值，可以降低因高估而选择错误动作的风险。

它可能带来保守或低估偏差；两个网络也并非统计独立，训练数据和目标相同。不能说取min保证无偏、保证不发散，或它本身解释了D相对C的差距。

### 56. 两个 Q 网络的参数、优化器和训练目标分别是否共享？你的版本实际怎样实现？

两个Q子网络的参数各自独立，但属于一个 `ContinuousCritic` 模块；SB3为整个critic创建一个优化器，损失把两个Q的均方误差相加。两个Q使用相同批次和同一个最小目标Q。

本项目的非图像 CombinedExtractor 没有可学习参数；SAC默认 actor/critic 不共享特征提取器。目标critic是在线critic的参数副本，经软更新，无独立梯度优化器。因此“两个Q各有一个独立优化器”不符合此版本实现。

### 57. 写出策略损失。为什么策略更新需要对采样动作求导？

最小化 `Lπ=E[α logπθ(aθ|x)-min_i Qi(x,aθ)]`。策略既要考虑熵，又要通过Q对动作的导数，把动作推向价值更高的方向。

因此动作必须能对策略参数求导，不能把采样后动作完全detach再期待这条Q梯度训练actor。critic参数在actor优化器之外，actor步骤只更新actor；实现仍可能对critic计算临时梯度，并非每次都会显式冻结其 `requires_grad`。

### 58. 重参数化＝把随机采样写成可对参数求导的变换。SAC 中具体如何使用它？

采样独立噪声 `ε~N(0,I)`，令 `u=μθ(x)+σθ(x)⊙ε`，再 `a=tanh(u)`。噪声分布与θ无关，动作通过可微变换依赖θ，因此可以把Q对动作的导数传回均值和标准差网络。

SB3通过高斯分布的可重参数化采样实现这条路径。评估 `deterministic=True` 使用确定性输出，不等于训练时没有随机策略。

### 59. 高斯动作经过 `tanh` 后，为什么动作的对数概率需要修正？漏掉修正会影响什么？

变量变换改变概率密度，应写 `logπ(a|x)=logN(u;μ,σ)-Σ_j log(1-tanh(u_j)^2)`，代码加小ε防止数值问题。多维修正需要求和。

漏掉雅可比项会使log_prob、熵正则及自动α更新所依据的概率不正确，尤其动作接近边界时误差大。此说明对应 `common/distributions.py::SquashedDiagGaussianDistribution.log_prob`，不是仅把高斯动作硬裁剪的分布。

### 60. 环境动作范围不是 `[-1,1]` 时，SB3怎样进行动作缩放？回放池里保存的动作处在哪个坐标范围？

SB3离策略采样器把环境范围动作映射到归一化[-1,1]坐标存进回放，执行前再反变换到环境动作空间。对上下界l、h，有 `a_env=l+(a_norm+1)(h-l)/2`。

Fetch本来就是[-1,1]，这一步数值上不改范围。`ActionGain`在环境包装层执行，发生在这之后；回放仍存增益之前的归一化策略动作。不要把包装器裁剪后的动作误说成SAC池里保存的动作。

### 61. 自动熵系数更新的目标是什么？为什么优化的常常是 `log(alpha)`？

使用 `η=logα`，`α=expη>0`，通过 `Lη=-E[η (logπ(a|x)+H_target).detach()]` 调整探索权重。把log_prob分支detach可防止α损失顺带更新actor。

优化log参数便于保持α为正，也改变了与直接优化α相比的数值尺度。它追踪的是目标熵约束，不是直接优化成功率，因此不能保证不会在无效动作维度上保留随机性。

### 62. 你的目标熵具体是多少？第四个无效动作维度是否仍参与了目标熵计算？

默认 `target_entropy='auto'`，SB3按动作维度设 `-prod(action_space.shape)`，这里为−4。本轮加载D seed0最终模型实测也为−4。

第四维虽在Push被屏蔽，仍参与log_prob求和与目标熵。若要改为只对有效维度定义策略，需配套修改动作接口及分布并重做对照，不能事后把当前模型当成3维SAC解释。

### 63. 密集奖励与稀疏奖励的数值尺度不同，是否可能改变奖励项与熵项的相对影响？自动调节熵系数是否彻底消除了这个问题？

会影响。密集奖励每步为负距离，稀疏奖励多数为−1，Q和策略损失中奖励与α熵项的相对大小可能不同。自动α根据目标熵更新，但critic的尺度、优化动态和探索轨迹并不因此完全不变。

所以B/C的差异不仅是“反馈更频繁”，也包括奖励形状和尺度。要拆开可做奖励缩放和归一化消融，但当前没有，不能说auto entropy已排除这个混杂。

### 64. `gamma=0.98` 对这个任务意味着什么？50 步之后的奖励权重大致是多少？

`γ=0.98`，相隔50步的权重为 `0.98^50≈0.3642`；50控制步约2 s。指数折扣使较远未来的影响变小，约35步权重减半。

`1/(1-γ)=50`只是常用折扣尺度，不等于算法只看50步。环境时间截断仍可bootstrap，因此不能把当前实验解释成严格的50步终止MDP而完全忽略后续价值。

### 65. `tau=0.005` 在目标网络更新中怎样使用？如果设为 1 或接近 0，会分别怎样？

目标参数使用 `θ̄←(1-τ)θ̄+τθ`，这里τ=0.005；默认每次训练更新都有机会更新目标，项目 `gradient_steps=1`。

τ=1会把目标立即复制为在线参数，减少平滑；τ接近0会跟随很慢，τ=0则冻结。过快或过慢都有代价，不能简单把更小τ等同于更稳定。相关批归一化统计的复制逻辑在源码中另有处理，本网络不依赖它。

### 66. 你的回放池容量、预热步数、批量大小、采样频率和梯度更新次数分别是多少？一百万环境步实际对应多少次更新？

池容量1,000,000、预热10,000、batch256、`train_freq=1`环境步、`gradient_steps=1`，单环境。SB3条件是 `num_timesteps>learning_starts` 后训练，因此一百万步对应990,000轮SAC更新。

本轮读取所有B–E最终zip中的 `_n_updates`，均为990,000；每轮含critic、actor与自动α各一次优化步骤。不能把“990,000轮”误写成总共只调用了990,000次optimizer.step；也不能拿与PPO含义不同的 `_n_updates`直接比较计算成本。

### 67. SB3 中策略、Q 网络、熵系数和目标网络的真实更新顺序是什么？与你问答稿中的概括是否完全一致？

本地SB3 2.7.0 `SAC.train()` 的顺序是：采回放（HER此时生成虚拟样本）→当前状态采策略动作和log_prob→算α损失并先更新logα→算目标Q→更新两个critic→用已更新critic评价此前采样的策略动作并更新actor→软更新目标critic。

还有一个细节：本轮损失使用的 `ent_coef=exp(log_ent_coef.detach())` 在α优化前已取值，因此α参数先被更新，不意味着本轮critic/actor立刻使用更新后的α值。旧 `INTERVIEW_QA.md` 把熵更新放在策略后面不准确，本轮已修正。精确依据是本地 `sac.py` 约220–291行。

### 68. 如果 Q 值快速变大、策略动作饱和、成功率却下降，你会先看哪三项日志？怎样区分正常数值尺度变化与训练发散？

优先联合看：critic loss与Q/TD误差分布，actor loss与动作饱和比例，α/log_std或策略熵及独立验证成功率。不同奖励、折扣和熵会改变合理Q尺度，Q数值大本身不能定性发散。

本项目默认日志有actor_loss、critic_loss、ent_coef与验证指标，没有常态记录Q分位数、TD误差和裁剪比例。因此现有日志可提示异常，但不能完整完成上述三类诊断；需要固定检查点抽样或补监控。

## 第五组：HER 的机制、实现与边界（69–85）

### 69. HER＝更换回放样本的目标并重算奖励。请用一条具体推物轨迹构造一个修改前、修改后的样本。

`learning/her_relabel_samples.csv` 的第0步使用seed99真实随机轨迹：动作约 `[0.01206,0.13018,0.02383,0.94437]`，下一已达位置约 `[1.349115,0.890680,0.424737]`，原目标约 `[1.380012,0.769509,0.424700]`，原奖励−1。

改用同回合第49条转移的下一已达位置 `[1.349115,0.890680,0.424784]` 为目标，重算奖励变0；状态和动作保持不变。这个示例物体几乎未移动，恰好说明HER能制造“达成新目标”的信号，却不代表已经学会原任务；正式HER仍使用库实现。

### 70. 一个目标条件转移样本包含哪些字段？重标记时哪些要改，哪些必须保持不变？

目标条件转移可以写 `(obs_t,a_t,r_t,obs_next,terminated,truncated,info)`，两侧obs都含 observation、achieved_goal、desired_goal。重标记要改两侧desired_goal并用新目标重算奖励，保持实际运动学状态、已达位置和动作不变。

终止条件如果依赖目标，理论上也可能需要重算；本Fetch任务成功不终止，所以库中保留原done并处理timeout适用。不是在所有环境中都只改reward即可。

### 71. 当前观测和下一观测中的 `desired_goal` 是否都要修改？漏改一个会发生什么？

目标条件Bellman样本的当前值和下一值必须属于同一个目标。如果只改当前obs，目标Q对应另一个任务；只改下一obs则当前Q又与奖励任务不一致。

实际 `_get_virtual_samples()` 对 `obs['desired_goal']` 和 `next_obs['desired_goal']` 都赋同一个new_goals。物体位置未改，因此转移仍是实际发生的。

### 72. 奖励重算使用当前状态还是下一状态的 `achieved_goal`？请指出你的实际实现依据。

用 `next_obs['achieved_goal']`。环境step先施加动作并推进仿真，再按新物体位置算这次转移奖励；用当前位置会错开一个时间步。

本地HER `_get_virtual_samples()` 经 `env.env_method('compute_reward', next_achieved, new_goal, infos, indices=[0])` 重算。这不是项目另写一套奖励，包装器直接委托到底层环境。

### 73. `future` 采样策略具体从哪些时刻选目标？你使用的 SB3 版本是否允许选择当前转移对应的已达成目标？

本版future在同回合从当前转移索引到最后转移索引间采样，左端包含当前转移，然后取被选转移的 **next_observations.achieved_goal**。若当前样本是 `s_t→s_{t+1}`，可选的目标因此从 `achieved(s_{t+1})` 开始。

所以“包含当前转移”不等于取 `s_t` 的已达目标。源码是 `randint(current_indices_in_episode,batch_ep_length)`，末端上界不包含，但可取最后有效转移；这比笼统说“严格未来某步”准确。

### 74. `n_sampled_goal=4` 在实现里意味着什么？一个 256 样本批次中，真实目标与重标记目标大约各占多少？

库计算虚拟比例 `her_ratio=1-1/(4+1)=0.8`。batch256中 `int(0.8×256)=204`条虚拟重标记样本，剩52条原目标样本，不是精确204.8条，也不是固定每条真实样本旁边带4条拷贝。

抽样可有放回，这个比率控制批次组成。正式设置由 `train()` 的HerReplayBuffer参数接入。

### 75. 这是否等于每一步环境交互都永久存储了五条样本？虚拟样本什么时候生成？

不是。回放主要保存真实转移及回合索引元数据，虚拟样本在 `sample()` 时抽未来目标并重算奖励，供当前梯度批次使用。

同一真实转移在不同采样时可能得到不同新目标；不能用 `1m×5`解释实际环境交互数或永久存储量。HER的收益是增加目标条件训练用途，而不是制造额外真实物理经验。

### 76. 为什么新目标要来自同一条轨迹？如果从另一条轨迹随便拿一个位置，哪些性质会改变？

同轨迹已达位置提供了一个真实访问过、与当前经历相关的候选目标，future还具有从当前之后访问到它的时间相关性。任意另一轨迹的位置可能很远、不可达或与当前状态几乎无关，得到大量负奖励，学习信号更弱。

只要动力学独立于目标，跨轨迹目标不必然让物理转移数学上非法；改变的是目标分布、可达性证据和训练效率。不能说“不是同一轨迹就必定无效”，但它已不再是本项目采用的future策略。

### 77. 更换目标后，为什么原状态转移仍然可以使用？这依赖“目标”和环境动力学之间的什么关系？

依赖物理转移核不因期望目标标签而改变，即给定实际状态和动作，换目标不改变物理演化。Fetch目标是任务标签/可视标记，不改变桌面或物体动力学，因此能重用同一实际转移。

E的执行增益改变了转移，但同条转移重标记目标时增益并未变；这与“目标独立于动力学”不冲突。隐藏增益仍会影响是否具备充分观测，不能由HER自动解决。

### 78. 如果目标位置会决定障碍物布局，直接重标记目标还正确吗？你怎样修改环境或方法？

若改目标同时改变障碍物布局，那么同一观测动作在新任务下可能产生不同下一状态，直接保留旧转移通常不正确。仅重算奖励无法修复动力学不一致。

可把布局作为固定上下文并限制只在相同布局内重标记、把可更换的目标与影响物理的上下文分开，或在新布局中重新仿真/采集。具体方法要重新定义MDP并验证，不是简单调整future参数。

### 79. HER 为什么能在没有完成原目标时提供学习信号？它是否需要先出现成功推物轨迹？

轨迹虽然没到原目标，却实际到过某些位置；以它们为新目标，部分转移可获得0而非−1，critic和目标条件策略能学习“到达这些位置”的关系。无需先成功完成原始目标。

但有效主动推物仍需要有价值的探索转移，HER不会凭空创造物体移动。如果始终没接触物体，学习信号主要来自静止目标，难以覆盖原任务。

### 80. 假设物体从头到尾没有移动，HER 能生成什么经验？为什么这种经验不一定能教会机器人主动推物？

若物体位置不变，future目标基本都是同一位置，重标记后许多样本奖励为0。模型可学到“保持当前位置”的经验，但这些数据没有说明怎样主动把物体推向别处。

本项目第69题的示例就接近这种情形：50条奖励都改变，不代表50条都包含有效推动。应避免把虚拟成功样本比例高直接解释成探索充分。

### 81. “HER 提高数据利用率”和“HER 解决探索问题”有什么区别？你的实验分别能证明到哪一步？

提高利用率是同一批真实转移可训练更多目标任务；解决探索则意味着策略更容易访问到有用的新状态或接触行为。HER可通过学习反馈间接帮助探索，但不保证发现所有必要行为。

本实验 C/D 支持“加入该HER机制后最终任务表现大幅提高”，并未单独测量探索覆盖或有效推动频率，所以不能声称已经证明HER独立解决了探索瓶颈。

### 82. D 相对 C 的收益是否可能来自目标分布、训练样本组成或奖励分布变化？怎样把这些机制进一步拆开？

C/D只改变HER接入，但HER本身就是一组联动变化：目标分布、真实/虚拟样本比例、奖励分布及目标条件学习覆盖。可以把大幅收益归到这套HER机制，不能仅凭总结果拆成某个机制占多少。

进一步可比较不同虚拟比例、future/final、匹配奖励比例的对照、以及回放中真实/虚拟成功统计；需要固定新验证集和预算。当前这些机制消融未做。

### 83. 为什么没有比较 `future`、`final`、`episode` 目标采样策略？对 FetchPush，各自可能有什么特点？

为控制规模，采用成熟默认future完成主对照，没有扩展所有HER变体。future目标与当前之后的可达经历相关；final更集中于回合末位置；episode可选整个回合，含当前之前位置，可能增加多样性但不保证从当前继续可达。

对FetchPush各自优劣需要实测，不能按直觉宣布future必然最优。当前结论只对应所用future和n_sampled_goal=4。

### 84. HER 与时间截断、真正终止、成功即结束之间是什么关系？如果改成成功时立即结束，重标记是否还只需改奖励？

Fetch成功不立即结束，通常50步由TimeLimit截断。SB3采样时将timeout的done屏蔽以允许bootstrap，回放仍需用回合边界组织future目标。

若改为成功即真正终止，done就依赖目标；更换目标可能让终止时刻改变，旧轨迹也可能缺少新任务下应有的后续数据。此时不能仅改奖励，需要兼容目标相关终止的重标记和采集方案，并核对库是否支持。

### 85. 你能否现场给一个批量 `compute_reward()` 写检查，验证输出形状、数值、阈值边界和原始环境奖励完全匹配？

先测形状与阈值边界，再用真实step返回值对照；不要把稀疏奖励0等同于 `is_success=True`。下例是项目接口的最小检查，真实正式奖励不变：

```python
import numpy as np
from run import make_env

env = make_env({'group': 'D', 'task': 'Push'})
try:
    a = np.array([[0., 0., 0.], [.05, 0., 0.], [.051, 0., 0.]])
    z = np.zeros_like(a)
    r = env.compute_reward(a, z, [{} for _ in range(3)])
    assert r.shape == (3,)
    np.testing.assert_array_equal(r, [0., 0., -1.])
    np.testing.assert_array_equal(env.unwrapped._is_success(a, z), [1., 0., 0.])
    obs, _ = env.reset(seed=12345)
    obs, reward, terminated, truncated, info = env.step(np.zeros(4, np.float32))
    recomputed = env.compute_reward(obs['achieved_goal'], obs['desired_goal'], info)
    assert float(recomputed) == reward
finally:
    env.close()
```

本轮运行时核验已执行批量边界部分，原CPU环境验收也检查奖励重算；完整上述示例的执行结果见本轮文档验收记录。

## 第六组：PPO 与比较公平性（86–102）

### 86. PPO＝通过裁剪概率比率限制部分更新收益的策略优化方法。写出裁剪目标，并解释每个符号。

最大化 `Lclip=E[min(ρ_t A_t, clip(ρ_t,1-ε,1+ε) A_t)]`，`ρ_t=πθ(a_t|x_t)/πold(a_t|x_t)`，`A_t`为采样时估计的优势，ε=0.2。本实现把它取负作为最小化损失，并加价值损失与熵项。

本项目默认 `ent_coef=0.0`、`vf_coef=0.5`；即使日志记录entropy_loss，A也没有通过非零熵奖励主动维持探索。不要把SAC自动α机制套到PPO上。依据：`ppo/ppo.py::train` 与构造默认值。

### 87. 当优势为正与为负时，裁剪分别限制什么方向？它是否硬性保证新旧策略距离不超过某个值？

优势正时，若ρ超过1+ε，继续提高该好动作概率不再获得额外代理目标收益；优势负时，若ρ低于1−ε，继续降低该坏动作概率也不再获得额外收益。另一侧并非对称地全部截断，`min`必须连同优势符号理解。

它不是对参数、所有状态的概率比或KL的硬约束。本项目 `target_kl=None`，也没有启用基于KL的额外早停，所以不能说每次更新都保证策略距离小于某个值。

### 88. PPO 为什么能对同一批数据更新多轮，却通常不能像 SAC 那样长期反复使用旧回放？

PPO保留最近一批rollout的旧动作log_prob和优势，在新策略与这一版行为策略相近的前提下，用概率比进行有限轮更新，随后丢弃旧批次重新采样。

长期使用很多代之前的数据，会使状态访问分布、优势和概率比严重失配；当前裁剪目标并不能把它变成任意旧回放都有效的离策略算法。SAC训练目标和数据使用方式不同。

### 89. 你的 `n_steps=2048`、`batch_size=256`、`n_epochs=10` 对一次 rollout 的采样量和更新次数分别意味着什么？

单环境每次采2048步，batch256，恰好8个mini-batch；更新10个epoch，因此每rollout通常80次梯度步骤。没有设target_kl早停，本项目按这一路径训练。

每一条采样转移每epoch通常被使用一次，总共10次，而SAC是对大池有放回采样。PPO的 `_n_updates`每epoch加1，不是每mini-batch加1；一个rollout该计数增加10。

### 90. 为什么 PPO 最终是 `1,001,472` 步？请用 rollout 大小算出来。

`ceil(1,000,000/2048)=489`个完整rollout，`489×2048=1,001,472`。比计划多1472步，是按完整rollout完成导致的预算取整，不是额外选取训练点。

最终模型 `_n_updates=4890`对应489×10个epoch；mini-batch梯度步骤为489×10×8=39,120。三个A模型的实际步数一致，报告保留实际值。

### 91. PPO 与 SAC 都使用两层 256 单元，是否意味着模型容量相同？演员、价值网络、双 Q 网络和目标网络的数量怎样比较？

PPO有actor与value两条MLP分支和各自输出头；SAC有actor、两个在线Q和两个目标Q，Q还额外输入动作。激活、初始化和分布也不同。

本轮加载最终模型统计：A策略共有149,257个参数；D的actor 76,040、在线critic合计150,530、目标critic合计150,530，总计377,100。目标Q不通过梯度独立学习，因此可训练在线网络参数是226,570，另有自动熵的标量；不要把包含目标副本的总数说成全部独立梯度参数。

### 92. 两种算法使用相同学习率，为什么不等于给予了同等合理的超参数配置？

两者梯度目标、采样分布、优化次数、奖励尺度和优化器状态都不同，同一个3e−4不保证都接近各自合理配置。统一学习率便于固定配方比较，但不是充分调参后的算法排行榜。

应把结论限定为当前配方和预算；若要比较各自最佳潜力，应给予相同调参资源并独立选参，不能只替表现差的一组无限调到满意为止。

### 93. 你的 PPO 使用什么激活函数、初始化方式、动作分布和优势归一化？哪些来自库默认值？

MultiInputPolicy使用Tanh隐藏激活、正交初始化，MLP/特征模块初始化gain通常√2，动作输出头0.01、价值头1；连续动作是对角高斯，初始log_std=0，默认不使用gSDE。不是SAC那种tanh压缩高斯，执行时会裁剪到动作范围。

优势默认按mini-batch归一化，`normalize_advantage=True`；默认梯度范数上限0.5。上述多数来自库默认而非项目独立设计。激活与参数维度已通过加载模型核对，初始化依据锁定版 `common/policies.py`。

### 94. GAE＝广义优势估计。写出计算形式，并说明 `gamma` 与 `lambda` 各控制什么。

`δ_t=r_t+γ m_t V(x_{t+1})-V(x_t)`，`Â_t=Σ_l (γλ)^l δ_{t+l}`，递推时在真正的回合边界停止跨回合传播，timeout价值另按第95题处理。这里γ=0.98、λ=0.95。

γ控制未来奖励折扣；λ控制多步残差混合，较小更依赖单步价值估计、通常方差小但偏差可能大，较大更接近较长回报估计。不能把两者都解释成“越大越好”或完全等价。

### 95. 你的 PPO 在时间截断处怎样处理价值 bootstrap？这一步在库的哪个阶段发生？

在 `OnPolicyAlgorithm.collect_rollouts()` 内，若done且info含 `terminal_observation` 和 `TimeLimit.truncated=True`，用终止前观测预测V，再把 `γV(terminal_obs)` 加到该步reward，之后存入rollout计算returns/GAE。

这样避免把50步截断当作物理吸收终止，也避免用自动reset后的观测估价值。底层真实reward没有被环境修改，这是算法收集阶段为学习做的处理；最终评估回报仍是原环境reward累计。

### 96. 如果策略熵下降很快、成功率停在 6%，你会怎样判断是过早收敛还是策略根本没有获得有效梯度？

先检查更新是否发生、梯度是否有限、KL/clip_fraction是否显示策略改变，再看动作分布与接触/推动覆盖。熵下降且有有效策略更新却只重复无接触行为，可能是过早收敛；梯度近零或优势异常则更像学习信号问题。

本项目A有非零KL和clip_fraction、但没有梯度范数及全测试动作汇总，因此不能定案。价值拟合好也可能只是拟合“不推动”的回报，不能替代行为证据。

### 97. 你记录了 `approx_kl`、`clip_fraction`、`entropy_loss` 和 `explained_variance` 吗？这些指标分别能支持哪些诊断？

有 `approx_kl`、`clip_fraction`、`entropy_loss`、`explained_variance`，另有value_loss等。KL提示更新幅度；clip_fraction统计概率比越过裁剪区间的比例，并不表示这些样本都恰好被最终目标截断；entropy_loss是负熵；explained_variance描述价值对回报方差的解释程度。

本轮摘录A三个种子最后有值日志：KL约0.00899–0.01185，clip_fraction约0.128–0.148，explained_variance约0.99993–0.99996。日志往往在下一轮训练前dump，不能把最后一条视为最后一个梯度步骤的即时诊断；这些值也不能证明学会推物。

### 98. 相同环境交互步数比较的是哪一种效率？相同实际耗时比较的又是什么？

相同环境步比较交互样本效率；相同墙钟时间比较当前软硬件条件下的实际计算与执行效率。离策略算法可能每步计算更多，却更充分利用昂贵的真实环境数据。

本项目仿真便宜、CPU更新占一定成本，不能把这里的墙钟排序直接迁移到真实机器人。两类图需要同时看，并说明验证和保存开销是否包含。

### 99. A 用约 0.56 小时，B 用约 3.57 小时。差异来自仿真、网络更新次数、批量运算，还是其他开销？你做过分项计时吗？

A约0.56小时，B约3.57小时，是完整训练会话的单模型均值。PPO约39,120个mini-batch梯度步骤；SAC有990,000轮actor/critic/α更新，更新工作量差异是一个合理解释，但网络、回放抽样和仿真也各有成本。

没有做分项profiling，也没有隔离共享CPU其他负载，不能给出各项耗时占比或说“差异完全来自某一项”。总时间还包含训练内验证与保存，见第146题。

### 100. 如果给 PPO 与 SAC 相同的 3.57 小时，结论可能怎样变化？现有结果能否回答这个问题？

PPO可能进行更多交互，也可能仍停在无效策略；现有固定步数结果无法回答最终表现。把平均吞吐率线性外推也不能替代真实运行，后期负载和学习行为未必一样。

可以提出固定墙钟预算的预定对照，保留实际步数和验证开销；不能把“PPO更快”自动转换为“相同时间必然更强”。

### 101. 如果允许两种算法分别调参，你如何分配公平的调参预算，并避免只把某一种算法调好？

先固定每种算法相同的trial数或总计算预算、每trial交互上限、验证场景和选择指标，允许各自搜索合理的特有超参数。调参种子/验证集与最终评估分离，按相同规则选一个配置，再用多个新训练种子测试。

应同时报告调参成本和最终训练成本。算法不同使trial成本不同，按trial数和按总CPU小时是不同公平定义，需要事先选定并解释；本项目未做这种系统调参。

### 102. A↔B 在实验设计上只改变算法标签，是否意味着可以把差异归因到某一个算法机制？怎样表述才准确？

设计表把A/B标为算法变化，但更换PPO到SAC会连带改变on/off-policy数据使用、价值结构、分布、激活、初始化、优化次数和熵处理。因此这是两套算法配方的比较。

能说“相同密集奖励与交互预算下，当前SAC配方的三种子平均表现高于当前PPO配方，且波动大”；不能把差距单独归因于回放、双Q或熵正则，除非额外设计机制消融。

## 第七组：动作增益与负结果（103–119）

### 103. 你的动作增益具体插在调用链的哪个位置？是在策略输出、动作归一化、环境内部缩放之前还是之后？

在 `ActionGain.step()` 环境包装层。策略动作已经由SB3变成环境动作范围，包装器对前三维乘g并裁剪，然后才进入Fetch内部0.05的位移缩放。它不是直接缩放关节力矩，也没有修改物体摩擦或目标。

训练E的g每回合随机一次，D训练固定1；测试均用固定gain。奖励接口不变，第四维不参与增益变换。

### 104. 输入动作第一维为 `0.9`、增益为 `1.4` 时，进入环境的数值是多少？实际放大倍数还是 1.4 吗？

`0.9×1.4=1.26`，裁到1.0，所以进入底层的是1.0，对应名义位移0.05 m。相对原0.9有效比例为 `1/0.9≈1.111`，不再是1.4。

因此高增益扰动是带饱和的分段变换。报告g只描述包装参数，不能保证每一个实际动作或实际末端位移都按该比例放大。

### 105. 为什么 `g=0.6` 与 `g=1.4` 虽然离 1 都是 0.4，却不代表对称的控制扰动？

g=0.6把所有有效平移动作收缩，通常不会增加饱和；g=1.4会放大，但部分动作被边界压平。它们的动作分布、方向比例和接触效果不对称。

固定50步还让低增益面临更强的完成时间压力，而高增益可能引起过冲或饱和。离1相同的标量距离，不意味着等难度或等强度物理扰动。

### 106. 你统计过不同增益下的动作裁剪比例吗？高增益时是否有很多动作被裁到同一个边界？

原正式训练与3900回合评估未系统记录裁剪前乘积和裁剪比例。视频CSV有六个案例的策略动作，可事后算案例内饱和，但不能代表全矩阵。

所以无法声称高增益时“多数动作被裁剪”或给出未测比例。第153题给出不改变控制行为的记录方案；若执行，应作为新增诊断单独归档。

### 107. 低增益会减小单位时间移动幅度。在固定 50 步任务中，成功率下降可能有多少来自“来不及”，而不是控制策略不稳？

有可能，而且当前数据无法量化占比。固定50步使速度收缩与执行误差耦合：即使方向选择正确，较小有效位移也可能无法及时完成。

需要观察距离随步数下降、剩余距离和达到目标的首次时间。只有最后成功率，不能区分稳步接近但超时、方向误判、反复修正或接触失败。

### 108. 怎样设计一个实验区分时间预算不足与真正的控制误差敏感？延长回合时还要控制哪些因素？

固定同一批已训练模型和场景，比较g=1与g=0.6在50/更长步数下的距离曲线、首次成功时间及最终稳定性。可把约50/0.6≈84步作为一个诊断预算，但必须说明这不是严格等价的任务。

延长回合会改变动作机会、接触动力学演化和策略输入分布，且训练模型未必见过那么长回合；不应顺便重训或改reward而混入更多因素。新结果应单列，不替换原50步正式指标。

### 109. 你为什么按回合采样一次增益，而不是每一步采样？两种设定对应什么不同的误差模型？

回合固定增益近似持续的执行标定偏差：一次任务中控制幅度一直偏大或偏小。每步随机更像快速变化的执行噪声，时间相关性与可适应性不同。

选择前者是原设计范围，不能说已覆盖所有控制误差。若比较二者，应匹配分布及其他条件，仍要承认不同时间相关性本身就是实验变量。

### 110. 增益没有输入策略，但在一个回合内固定。对无记忆策略来说，这会不会造成部分可观测问题？

完整状态可写 `(physical_state,gain)`；当前策略输入不含gain，也没有历史记忆。同一可见物理观测配同一动作，在不同gain下会产生不同下一状态，因此严格说可能是隐藏参数的部分可观测问题。

这不妨碍无记忆反馈策略在一定范围内成功，但会限制它根据历史识别参数的能力。加入gain输入可测试知道参数的上限，历史/递归策略可测试识别能力，当前均未做。

### 111. 策略每一步读取新状态，就一定能够估计增益吗？反馈控制与显式识别增益有什么区别？

每步观察新状态并纠偏是反馈控制：即使不知道g，也可能通过连续调整完成任务。显式识别则需要把动作与前后状态变化联系起来估计g，通常需要历史或内部记忆，并受接触和动力学混杂影响。

当前前馈策略没有显式增益估计头，所以不能说“它已经在线识别出g”。只能说观察到一定误差下仍有较高任务成功率。

### 112. 报告把“D 已能通过闭环反馈补偿误差”列为解释。你有什么实验能验证它，而不只是看最终成功率？

可比较同一模型在正常反馈、观测延迟/冻结、以及相同动作序列开环执行下的表现，并记录扰动后的纠偏轨迹。若移除及时反馈显著伤害误差条件下表现，而正常状态反馈能恢复，才支持反馈发挥关键作用。

这些操作也会改变观测分布，需加标称条件对照。当前“D已有闭环补偿”只是合理解释，不是已完成机制实验的结论。

### 113. E 训练时随机采样增益，D 不采样。你怎样保证额外随机数调用不会改变物体和目标的初始分布？

包装器使用自己的 `np.random.default_rng()`，显式seed时由 `SeedSequence([seed,1729])`派生，不消耗底层环境的 `env.np_random`。reset先由底层生成初态，再从独立流采g。

因此相同场景seed可以保持物体与目标初始状态配对；原CPU验收有配对检查。它避免额外增益采样直接改变场景随机流，但整个训练中策略轨迹和采样数据仍会因动作不同而不同。

### 114. E 比 D 正常成功率低 1.7 个百分点，这是否说明随机化损害了标称性能？三个种子足够支撑多强的判断？

D为98.6667%、E为97.0%，样本均值差−1.6667个百分点，说明本次三个种子的观测均值更低。不能只凭这个差和三个种子就证明随机化必然损害总体标称性能。

应报告每个种子和差异不确定性；E自身波动也更大。准确措辞是“本次未观察到标称收益，均值略低”，而非已经建立普遍负因果结论。

### 115. `g=0.6` 时 E 为 `77.0±16.1%`，D 为 `85.0±7.2%`。是所有 E 模型都更差，还是主要由一个种子导致？

D为93%、83%、79%；E为75%、94%、62%。按同训练seed标签相减是−18、+11、−17个百分点，不是所有E都更差，也不是只有一个种子造成负均值；两个更差、一个更好。

E种子2较低，但seed0也明显低。训练seed标签对应一种配对呈现，并不保证两算法全过程共享完全一致随机轨迹；三个样本不足以概括总体差异来源。

### 116. `g=1.4` 时 E 略好，`g=0.6` 时 E 更差。把两者平均是否掩盖了方向性差异？

会。g=0.6时E−D=−8.0个百分点，g=1.4时约+1.6667，等权平均约−3.1667。一个标量不足以表达低增益下降和高增益轻微上升的区别。

应同时给五档曲线、逐种子值和范围外摘要。高增益的正差也很小且样本有限，不能据此宣称已经证明单侧鲁棒性改善。

### 117. 范围外只测两个点，为什么选择 0.6 和 1.4？这些点和等权平均方式是在看结果前确定的吗？

0.6/1.4和完整五档增益在原始完整设计、正式配置与协议中事先列出，且确实位于E训练区间[0.8,1.2]之外。它们只是两个指定误差点，不代表连续范围上所有扰动。

但现有事前文字没有清楚写出“范围外两点等权平均作为主指标”的独立预注册条款。报告的等权平均是透明的描述性汇总，应明确公式并保留单点数据，不能声称该汇总权重已有严格事前预注册。原题对这一点的追问有价值。

### 118. “没有观察到收益”“随机化没有用”“随机化使性能下降”，这三句话分别需要什么证据？

“没有观察到收益”适合当前有限实验：测到的均值未提高，并承认功效和范围有限。“随机化没有用”需要更广任务、范围、预算和调参下持续无收益，甚至明确实用等效界限；当前不支持。

“随机化使性能下降”若作为总体因果结论，还需设计充分的重复实验和可靠不确定性分析。当前可以说“本次配置下观测到平均下降”，不要省略限定。

### 119. 如果继续研究，你怎样区分随机化范围不合适、训练预算不足、隐藏参数难以识别、随机种子波动这四种解释？

范围问题：在固定预算下比较多个事先确定的随机化区间；预算问题：固定区间跑预定更长训练；隐藏参数问题：比较提供gain、历史/递归策略和原前馈策略；种子问题：增加独立训练种子并报告分布。

应分阶段控制变量并使用新验证/最终测试场景，预先规定停止和选参规则。当前没有足够数据在四个解释中确定主因，本轮也未启动这些实验。

## 第八组：统计、测试集与图表（120–136）

### 120. 现场推导 3,900 个最终测试回合的组成；D/E 在 `g=1.0` 下是否被重复计算？

A/B/C各3个模型，每模型标称增益下100回合：`3×3×100=900`。D/E各3个模型，每模型5档gain各100回合：`2×3×5×100=3000`，合计3900。

D/E的g=1已经包含在五档中，正常条件表直接复用这一档，没有再多算600回合。本轮读取15个评估CSV，得到39个“模型×gain”组合，共3900行。

### 121. 3,900 次评估中有多少个不同的初始场景？“回合数很多”为什么不等于场景多样性很高？

使用100个场景seed：20000–20099，各模型和增益重复使用以形成配对。初态随机过程在同版环境和独立gain RNG下应一致；并不是3900个独立初始场景。

3900描述评估执行量，100描述场景覆盖，3描述每组训练重复数；三者不能替代。反复在同场景上测试不同模型增加比较信息，但不会自动扩大环境多样性。

### 122. 训练随机种子、验证场景种子和测试场景种子分别控制什么随机过程？

训练seed0/1/2用于网络初始化、策略采样、回放抽样及训练环境随机流；环境内部也有独立的Generator，gain又有自己的派生Generator。具体消耗顺序会随算法与轨迹不同而不同。

验证每次显式reset到10000–10019，用于训练过程监控；最终测试显式reset到20000–20099。pilot使用99，不进入正式三种子均值。seed编号只是初始化方式，不保证两个不同算法经历完全相同随机过程。

### 123. 测试种子与训练种子不同，就足以证明没有数据泄漏吗？训练和测试是否仍可能来自同一分布？

如果反复看测试结果后改算法、选模型，即使测试seed与训练seed不同，仍可能发生评估信息泄漏。需同时检查开发决策和模型选择规则。

本项目标称训练/测试来自同一场景采样分布，只是随机实现不同；范围外仅指0.6/1.4增益相对E训练区间。不能把独立seed写成对新机器人、新布局或任意分布的泛化证明。

### 124. 不同方法使用相同场景种子，你怎样确认实际生成的物体、目标和机器人初始状态确实一致？

不能只看seed数字。应对相同seed分别建环境，比较reset的observation、achieved_goal、desired_goal；必要时比较底层qpos/qvel。原CPU验收已做gain初态配对检查，gain使用独立随机流也有源码依据。

正式每回合CSV没有存完整初始qpos，因此不能声称3900回合都逐关节留有初态比对记录。本轮条件统计依赖锁定版环境的确定性reset和原零动作场景记录，并非重新取证全部仿真初态。

### 125. 给定 B 的三个成功率 `53%、6%、6%`，现场计算均值与样本标准差，解释为什么除以 2 而不是 3。

用百分数数值计算，均值 `m=(53+6+6)/3=21.6666667`；样本标准差为：

```text
s = sqrt(((53-m)^2+(6-m)^2+(6-m)^2)/(3-1))
  = sqrt(736.3333333)
  ≈ 27.13546265 个百分点
```

除以n−1是样本方差估计的自由度校正，均值已由这三个样本估出。报告写21.7±27.1%；它不表示三次运行都集中在均值附近，也不是均值标准误。复算见本轮JSON。

### 126. 三个训练种子的标准差，与一个固定模型在 100 次测试中的抽样不确定性有什么区别？

跨训练seed标准差描述初始化、探索和训练随机性导致的模型差异；固定模型100个场景的成功率还受场景抽样影响。前者与后者不是同一个量。

当前同一批100场景在所有模型复用，会使模型间测量存在场景相关性。简单把300回合当独立训练重复，或把训练seed的SD称作二项分布误差，都会误读统计含义。

### 127. 如果把一个模型测试 10,000 次，能否弥补只有三个训练种子的不足？它减少了哪一类不确定性？

一个模型测一万次，可更精确估计这个模型对场景分布的成功概率，并扩大场景覆盖；它仍只代表一次训练结果，无法显示训练是否经常失败。

如果重复的还是相同100场景、且策略评估确定性，信息增加可能很有限。要减少训练过程不确定性，需要训练更多独立模型，而不是只扩大某一个好模型的测试回合数。

### 128. D 为 `98.7±1.2%`，能否把“±1.2%”读作模型真实成功率一定在这个范围内？

D三个模型98%、98%、100%，跨模型均值98.6667%，样本SD约1.1547个百分点，四舍五入写98.7±1.2%。这是对这三次训练结果离散程度的描述。

它不是“真实成功率一定落在97.5%到99.9%”，也不是95%置信区间，更不含所有场景和训练分布上的可靠性保证。三个训练种子的总体推断本来就有限。

### 129. D−C 的 92.7 是百分点还是相对百分比？二者怎样换算，哪个更适合当前结果？

绝对差为 `98.6667%-6%=92.6667`个百分点，写+92.7个百分点。若按相对百分比，则为 `(0.986667-0.06)/0.06×100%≈1544.4%`，约为基线的16.44倍。

弱基线很小，相对百分比非常夸张，项目更适合报告绝对百分点和两个原成功率。二者不能混写成“提高92.7%”。

### 130. 范围外 D=89.8%、E=86.7%，显示值相减为 −3.1 个百分点，报告为什么写 −3.2？请给出未四舍五入的计算过程。

D各seed的两点均值是92%、89%、88.5%，总均值89.8333333%；E为87%、95%、78%，总均值86.6666667%。未舍入相减：`86.6666667−89.8333333=−3.1666666...`个百分点，保留一位小数为−3.2。

先显示成86.7和89.8再相减得到−3.1，是先舍入后运算导致。计算应始终使用原始精度，最后展示才舍入。

### 131. 范围外的标准差怎样算？是先对每个种子的两个增益结果求平均，还是先汇总两个增益的标准差？

先按训练seed对g=0.6和1.4的成功率等权平均，再对三个seed的均值求样本SD：D约1.89297个百分点，E约8.50490，显示1.9和8.5。

不能把两档SD直接求平均，因为它忽略同一训练模型跨gain的相关性；也不能把6个“模型×gain”当成6次独立训练。定义和实现见 `summarize_results.py` 的ood段及本轮JSON。

### 132. 要对 D/E 差异构造不确定区间，你会按回合、场景还是训练种子重采样？怎样处理这些层级的相关性？

需要同时考虑训练模型和场景两个交叉维度：一层重采样训练模型，一层重采样场景ID，并让同一场景的D/E和两个gain保持共同场景索引；一个模型在不同gain的数据应作为同一训练模型的成组结果。不能把所有回合打散独立抽样。

若训练seed配对是事先设计且其共同随机因素有意义，可以成对重采样；仅仅标签同为0/1/2，不足以保证强配对，应考虑两组训练模型独立重采样并保留场景配对。只有3个训练模型时，bootstrap区间本身也很不稳定，应透明报告且不把它当增加样本量。当前未生成这种置信区间。

### 133. 每个验证点只测 20 个回合，成功率的最小变化单位是多少？学习曲线中的小幅起伏能解释成训练不稳定吗？

每点最小变化单位是 `1/20=5`个百分点。某个场景由失败变成功，就会跳5个百分点；固定验证场景还会让相邻点的误差相关。

因此小幅起伏不能直接等同训练不稳定或发散。应该看持续趋势、分种子曲线和行为变化；B同验证集90%到55%的下降是明显观测变化，但原因仍需诊断。

### 134. 图里的阴影截在 0–100% 内，会怎样影响读者对不确定性的直观判断？是否应该同时给出分种子数据？

成功率有界，所以图把 `mean±SD`显示限制在0–100%。边界附近阴影会不对称、显得更窄，读者可能低估原始SD；这不是置信区间，也不是截断后重新估计的统计量。

应该保留未裁剪的数值表及单seed线。现有学习/鲁棒性图保留细线，表中给样本SD；学习曲线只聚合三seed共同存在的步点，没有缺失插值。

### 135. 你怎样证明最终测试没有用于调参或选模型？有哪些配置冻结、运行时间、模型哈希和测试时间记录？

支持材料有事前配置/冻结runner、seed99准入记录、正式各目录config/system、训练及测试日志顺序、固定预算最终模型而非best模型、最终交付哈希清单。E中断后重跑使用相同学习参数，只调整保存间隔。

但本地文件时间和后补哈希不是不可篡改的第三方审计，不能数学证明所有开发决策从未看过测试。准确说是“现有协议与运行记录符合该流程”。本轮复核与视频分析都在原模型冻结后完成，不能倒写成事前证据。

### 136. 事后零动作诊断和视频案例分析使用了测试集；如果下一轮据此修改算法，还能把同一组场景称为完全未见的最终测试吗？

不能。如果根据这100场景中的失败模式修改算法、包装或调参，这些场景已参与开发，应视作诊断/验证集。下一轮需另定未参与开发的场景用于最终评价。

### 138. 你锁定了哪些依赖版本？为什么“代码 SHA-256 相同”不能单独保证运行行为相同？

### 139. 每个训练目录怎样关联配置、模型、训练曲线和最终评估？如何发现误加载了另一个组的模型？

训练目录名是 `runs/formal_20261022/D_seed0` 这类组/seed标识，内含config、system中的runner哈希、progress/validation、summary和final整包。评估summary记checkpoint绝对路径、group、training_seed和各gain指标；逐回合CSV与汇总表按同一标识关联。

### 140. 正式模型全部从零训练的证据是什么？是否存在续跑、旧回放池或预训练权重被意外带入的可能？

正式配置中没有 `resumed_from`，启动命令没有 `--resume`，冻结代码的该分支会新建模型和回放；模型步数与更新次数吻合预算，正式seed与pilot区分。E旧中断目录被归档，正式E是同参数重新从零跑。

本轮读15个config和zip元数据，未发现resume字段，B–E均990,000次更新。它们支持“按代码与记录从零训练”，但不是对所有历史文件访问的取证证明；仅看最终步数本身也不足以排除预训练，必须结合命令和源码。

### 141. 保存检查点时，网络、优化器、熵系数、回放池、仿真状态和随机状态，哪些被保存，哪些没有？

`model.zip`保存网络、算法元数据和相应优化器状态；SAC包含actor/critic优化器、目标critic、logα及其优化器，PPO保存策略/价值网络与优化器。SAC回放另存 `replay.pkl`，有真实转移及HER的回合索引、timeout等数据。

没有完整保存MuJoCo正在进行的仿真状态，也没有项目级打包Python/NumPy/Torch及各环境Generator的全部当前随机状态。保存一个seed字段不等于保存随机流当前位置。PPO rollout也不作为可无缝延续的当前采样缓冲恢复，所以不宣称逐步一致续跑。

### 142. 模型保存成功但回放池只写了一半，程序怎样识别这个检查点不可恢复？完成标记在什么时刻写入？

`save_bundle()`先创建新目录，依次写model、SAC回放和config，最后写 `complete.json`。`load_bundle()`要求完成标记存在；半写到回放就中断时，不会有最后标记，应该拒绝加载。

这是“完成标记”协议，不等于具有fsync/事务或能检测所有后续磁盘损坏。当前加载器没有给每个文件做哈希核对，也可能在损坏pickle读取时才报错；协调器另查文件和身份。若要加强，可加入大小/哈希清单和原子重命名，但本轮没修改冻结实现。

### 143. `--steps` 在恢复命令中表示总预算还是新增预算？如何防止恢复后重复计算或超出正式训练预算？

原runner `--steps` 是累计目标。比如检查点30万步，要求100万，则 `remaining=1000000-300000=700000`，`learn(...,reset_num_timesteps=False)`；目标不大于当前计数会拒绝。PPO还可能按rollout略超。

Zoo的 `-n`恢复语义不同：是新增learn预算，默认会重置计数及学习阶段相关进度。后补短验收已验证300步后新增200步，保存计数变200、回放累计500、更新计数继续增长。不能把两套命令的数字直接互换，恢复时需明确剩余预算与文件来源。

### 144. 在 SB3 的向量环境接口中，回合结束后下一观测可能已是 reset 后的观测。你如何避免把它误当作终止状态来学习？

SB3 VecEnv中 `done=True`时返回的new_obs通常已经是下一回合reset观测，真正最后观测在 `info['terminal_observation']`。离策略 `_store_transition()` 会用它替换回放中的next_obs；PPO timeout bootstrap也从这里取终止前观测。

同时 `TimeLimit.truncated`用于区分timeout。原项目使用SB3标准收集器，未自行重写该链；若现场用普通Gymnasium单环境评估，则step直接返回当前最后观测，不能把两种API混为一谈。

### 145. 训练期间调用验证，会不会消耗训练正在使用的随机数状态，改变之后的学习轨迹？你怎样隔离和检查？

训练回调在验证前保存Python `random`、NumPy全局、Torch CPU及已初始化CUDA的随机状态，`finally`恢复；验证新建环境，逐回合显式seed，独立于训练环境Generator。gain也用独立Generator。

这些措施针对验证消耗随机数的影响，源码路径明确；不等于已做过完整“开验证/关验证两次训练逐参数一致”的实验证明。当前没有这类严格A/B核对，也不能声称回调没有任何计时或运行模式影响。

### 146. 你的计时包含哪些步骤：预热、训练内验证、检查点保存、最终保存？不同组的统计口径一致吗？

`train()`在调用learn前启动计时，learn返回并完成 `save_bundle()` 后取耗时。因此包含预热交互、训练更新、训练内验证、周期保存及最终模型/回放保存；不包含此前创建环境/网络、system与pip freeze准备，也不含独立最终测试和视频报告。

五组采用相同会话口径，但SAC保存回放更大，E重跑时周期保存更频繁，因此不是纯梯度计算时间。学习曲线的 `session_seconds`是在各验证完成时采样，不能混同最终summary的全部会话耗时。

### 147. 服务器有大显存 GPU，最后为什么全部使用 CPU？拿出实际测速依据，并说明共享 CPU 负载怎样限制耗时结论。

前期CPU基准是D组Push5万步，耗时513.738 s，约97.326步/s，含预热后4万次更新；基准最初在uv隔离环境执行，核心版本与最终conda相同，并做过加载继续更新验收。正式协议写明当时GPU有占用，因此选可用CPU、最多3进程各2线程尽快完成。

**没有同配置GPU测速，不能说CPU比GPU更快或已证明CPU最优。** 大显存不自动加速小网络与单环境仿真；共享CPU负载又使真实耗时不是严格硬件基准。应展示现有基准记录并坦承缺失对比。

### 148. 视频中的六个案例都使用训练 seed 0，为什么？这能代表 E 在三个种子间的波动吗？

案例生成器按预设展示条件从seed0选真实场景，简化模型切换并展示标称、低/高增益及失败行为；它们是挑选的说明性案例，不是随机抽样。

不能代表E三个训练seed的波动，尤其g=0.6时E的75/94/62%差异很大。代表性证据应看全量表与分种子曲线，必要时另加不同训练种子视频，而不是用seed0替代统计。

### 149. 视频包含四个成功案例和两个失败案例，但整体统计不是这个比例；你怎样避免观众把展示比例误认为成功率？

视频选择比例是为了展示行为，不能算4/6=66.7%作为算法成功率。标题与说明应明确“案例展示”，完整指标来自所有固定测试回合。

成功例还排除了初始距离≤8 cm、没有明显物体移动的情况，避免拿自然初始成功冒充有效推物；这个筛选只适用于展示，不改变100回合评估分母。出处：`make_case_video.py` 和cases.json。

### 150. 视频通过重复播放和冻结末帧扩展到 90 秒。每个案例实际对应多少仿真时间、多少条独立轨迹？如何回查原始记录？

共6条独立测试轨迹，每条50个控制步、2 s仿真；包含初始帧后是51帧，25fps视频原片约2.04 s。每个展示段把同条原片重复三次，再冻结末帧凑到10 s，重复不是新的试验。

全片开场10 s、六例各10 s、结尾两张说明卡各10 s，总90 s/2250帧。每例可从cases.json查group、训练seed、gain、场景seed、模型哈希，再回到对应50行CSV和原片。

### 151. “未形成有效推动”“方向偏差”“未完成精确到位”的分类阈值是什么？你怎样处理轨迹启发式与真实接触情况不一致的案例？

代码先看最后成功；否则物体最大位移<0.01 m记“未形成有效推动”。设 `projection=dot(final-initial,goal-initial)/||goal-initial||²`：曾成功且projection>1记“推过目标”，曾成功但不满足前者记“到达后离开目标”；未曾成功且projection<0记“方向偏离”，其他记“未完成精确到位”。

这是位置轨迹启发式，不是真实接触判定。“推过目标”也不严格保证沿目标直线越过，可能有侧向分量，应结合轨迹理解。若与接触信息冲突，保留原数据、标为启发式不确定，并补接触对/力证据；不要把分类名说成已测物理根因。

### 152. 现在给你一个陌生检查点，不看现成问答稿：请写出加载模型、运行 100 回合、统计最后一步成功率并导出逐回合距离的程序。

最小逻辑是：确认算法与奖励环境 → 创建相同动作包装 → 用SB3 load绑定环境 → 每回合显式reset指定scene seed → deterministic predict到终止/截断 → 记录最后info成功和最后物体距离 → 输出逐回合CSV与模型身份。

可运行完整程序已写在 [learning/interview_eval_100.py](../learning/interview_eval_100.py)，核心循环为：

```python
records = []
for scene_seed in range(seed_base, seed_base + 100):
    obs, _ = env.reset(seed=scene_seed)
    for step in range(1, 51):
        action, _ = model.predict(obs, deterministic=True)
        obs, reward, terminated, truncated, info = env.step(action)
        if terminated or truncated:
            break
    records.append({
        'episode_seed': scene_seed,
        'success': int(bool(info['is_success'])),
        'distance_m': float(np.linalg.norm(obs['achieved_goal'] - obs['desired_goal'])),
    })
success_rate = float(np.mean([r['success'] for r in records]))
```

实际程序还负责算法选择、SAC/HER环境绑定、模型哈希、CSV/JSON导出和新目录保护。例如：

```bash
source /home/zhsu/jyluo/projects/mujoco-fetch-push-rl/env.sh
python learning/interview_eval_100.py \
  --model runs/formal_20261022/D_seed0/final/model.zip --group D \
  --episodes 100 --seed-base 20000 --gain 1.0 \
  --out checks/my_interview_eval_D_seed0
```

陌生检查点需要先确认算法、环境版本、归一化和自定义包装，不能仅凭zip文件名猜。SAC预测可用 `buffer_size=1` 避免无意义分配百万容量；使用HER时即使只预测也要给load传环境。默认不会加载旧回放或调用learn。

### 153. 现在让你只增加一个功能：记录动作裁剪比例，并按增益和训练种子汇总。你会修改哪个函数、如何验证记录正确、怎样保证它不改变原训练行为？

应在 `ActionGain.step()` 中读取 `float32(action[:3])*gain`、在裁剪前判断绝对值是否>1。定义两个指标：分量裁剪率=`被裁分量总数/(3×控制步数)`；步裁剪率=`至少一维被裁的步数/总步数`。恰好等于边界不算发生裁剪，第四维不纳入。

为保留正式代码，本轮在 [learning/interview_clip_observer.py](../learning/interview_clip_observer.py) 增加诊断子类：先计算记录量，然后**把原动作只交给原step一次**，不额外采随机数、不重复乘gain、不改reward/obs。按训练seed与固定测试gain汇总；随机训练gain连续采样时应预定义分桶，不能把不同增益胡乱合并。

验证包括0.9×1.4会被裁、0.5×1.4不会被裁、g=0.6时合法原动作不触发新增裁剪，以及同场景同动作序列下观察器与原包装的全部观测、奖励、终止信息逐步一致。本轮做了这些小型行为等价核验，记录在文档验收JSON。未给既有3900回合补造裁剪数据，也没修改正式runner。
