**1．最终要做成什么**

场景很明确：桌面上随机放置一个方块和目标点，机械臂用闭合的夹爪把方块推到目标附近。策略每一步读取物体、机械臂和目标的状态，输出末端移动指令。

正式环境用 `FetchPush-v4`，密集奖励版本用 `FetchPushDense-v4`；入门用 `FetchReach-v4`。这些名称已在官方环境注册代码中确认，部分文档示例仍写着旧的 `v3`，实现时统一使用 `v4`。[环境注册代码](https://github.com/Farama-Foundation/Gymnasium-Robotics/blob/main/gymnasium_robotics/__init__.py)

| 项目要素 | 固定设计 |
|---|---|
| 输入 | `observation`：25 维状态；`achieved_goal`：3 维当前物体位置；`desired_goal`：3 维目标位置 |
| 输出 | 4 维动作，前三维控制末端沿 x、y、z 的移动；夹爪在 Push 中锁定，第四维不起作用 |
| 控制频率 | 25 Hz |
| 单次任务长度 | 50 个控制步，约 2 秒仿真时间 |
| 成功条件 | 方块与目标的距离小于 0.05 米 |
| 主要评价 | 第 50 步是否成功，以及最终距离 |
| 感知方式 | 使用仿真器提供的状态，不加入摄像头识别 |

这些是环境自身的设定。[FetchPush 官方说明](https://robotics.farama.org/envs/fetch/push/)

这里有一个面试必须讲清的边界：**策略输出的是末端位移指令，底层运动由环境执行。**这个项目能证明你做过机器人强化学习实验，但不能据此宣称实现了关节力矩控制、视觉感知或实机部署。

**3．算法为什么这样选，实验怎样形成因果关系**

PPO＝用近期采样的数据更新策略，并通过裁剪目标限制过大的策略更新；SAC＝重复利用经验回放中的历史数据，同时鼓励策略保留一定随机性的连续控制算法。前者适合作为常见对照，后者适合作为这个项目的主算法。[PPO 文档](https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html)、[SAC 文档](https://stable-baselines3.readthedocs.io/en/master/modules/sac.html)

HER＝事后经验回放：一次推物没有到原目标，却到达了另一个位置，可以把那个位置重新当作目标，用这段经历继续学习。例如原目标是 A、实际推到了 B，HER 会生成“目标是 B”对应的训练样本，并重算奖励。SB3 通过 `HerReplayBuffer` 把它接入 SAC 等使用经验回放的算法。[HER 文档](https://stable-baselines3.readthedocs.io/en/master/modules/her.html)

正式实验固定为以下五组：

| 编号 | 方法 | 奖励 | 训练时控制误差 | 要回答的问题 |
|---|---|---|---|---|
| A | PPO | 密集 | 无 | 常见策略梯度方法的表现怎样？ |
| B | SAC | 密集 | 无 | 与 A 相比，样本效率和耗时怎样？ |
| C | SAC | 稀疏 | 无 | 与 B 相比，奖励变稀疏后发生什么？ |
| D | SAC＋HER | 稀疏 | 无 | 与 C 相比，重标记目标是否有效？ |
| E | SAC＋HER | 稀疏 | 有 | 与 D 相比，训练时加入控制误差是否提高鲁棒性？ |

密集奖励＝每一步返回物体到目标距离的负值；稀疏奖励＝在目标范围外返回 −1、进入范围返回 0。正式实现调用环境自身的 `compute_reward()`，避免 HER 重算奖励时与原环境不一致。[奖励实现](https://github.com/Farama-Foundation/Gymnasium-Robotics/blob/main/gymnasium_robotics/envs/fetch/fetch_env.py)

**比较只沿 A↔B、B↔C、C↔D、D↔E 展开。**例如拿 A 和 D 的差距直接解释“SAC 比 PPO 好”，就同时混入了奖励设计和 HER 两个因素。

这里的消融＝只移除或改变一个因素，观察结果变化。C↔D 已经是 HER 消融，D↔E 已经是控制误差训练消融，第一版不需要再加入 TD3、复杂网络或更多任务。

**4．你自己的扩展：控制指令有误差时还能不能推准**

扩展选“动作增益误差”，因为它实现范围小、含义明确，而且不会改动 HER 所依赖的目标和奖励定义。

动作增益＝执行端对移动指令的放大或缩小比例。例如策略要求移动 1 厘米，执行端实际按 0.8 厘米或 1.2 厘米的指令执行。实现规则为：

\[
a_{\text{执行},\,0:3}
=\operatorname{clip}(g\,a_{\text{策略},\,0:3},-1,1)
\]

前三维动作乘以增益 \(g\)，第四维保持原样；这是对环境输入指令的修改，实际末端运动还受仿真约束影响。

| 阶段 | 增益设置 |
|---|---|
| D 组训练 | 固定 `g = 1.0` |
| E 组训练 | 每次任务开始时，从 `[0.8, 1.2]` 均匀采样一次，整次任务保持不变 |
| 最终测试 | 分别固定 `g = 0.6、0.8、1.0、1.2、1.4` |

`0.6` 和 `1.4` 超出训练范围，可以检查对更大控制误差的泛化能力。增益不输入策略，因此这也是一个简化的未知执行误差场景。

你最终应当得到一张“控制增益—成功率”曲线，比较 D 和 E。假设 E 在正常环境中略有下降、在误差条件下更稳，就可以讨论性能与鲁棒性的取舍；如果没有改善，也要保留结果，检查误差范围、训练预算或策略是否本来就能通过反馈修正。

这个实验支持“仿真中的控制误差鲁棒性”结论，实机迁移能力需要另行验证。

**5．训练参数、算力和复现规则**

第一版使用 Python 3.11，安装兼容的正式版依赖；跑通后把实际版本锁定到 `requirements-lock.txt`，记录操作系统、CPU、GPU和代码提交编号。以下参数是预实验起点，不是已验证的最优配置。

| 参数 | PPO | SAC / SAC＋HER |
|---|---|---|
| 策略接口 | `MultiInputPolicy`，接收字典观测 | 相同 |
| 隐藏层 | 策略与价值网络各两层、每层 256 单元 | 策略与 Q 网络各两层、每层 256 单元 |
| 学习率 | `3e-4` | `3e-4` |
| 折扣因子 | `0.98` | `0.98` |
| 批量大小 | 256 | 256 |
| 采样与更新 | `n_steps=2048`、`n_epochs=10` | 单环境每采样一步更新一次 |
| 其他 | `clip_range=0.2`、`gae_lambda=0.95` | 回放容量 `1_000_000`、预热 `10_000` 步、`tau=0.005`、自动调节熵系数 |
| HER | 不使用 | `future` 目标采样、`n_sampled_goal=4` |

先不开观测与奖励归一化，减少初期变量；如果预实验发现必须加入，就记录为明确改动，并确保对应对照保持一致。HER 的目标选择参数与接口可参考官方实现。[HER 参数说明](https://stable-baselines3.readthedocs.io/en/master/modules/her.html)

正式预算：**五组 × 三个训练随机种子 × 每组 100 万步，约 1500 万环境步。**随机种子＝控制初始化和随机采样的整数，正式使用 `0、1、2`；预实验使用 `99`，调好配置后再启动正式三种子实验。

100 万步是第一档预算，不保证收敛。若预实验显示需要 200 万步，应在正式比较前统一调整相关组的预算；不要只给表现最好的方法更多训练时间。

硬件先按“16 GB 内存的电脑可以开发与短跑，实验室机器承担正式实验”规划。GPU是否更快要实测，小网络也可能主要耗时在环境交互。用开启梯度更新后的 5 万步测总速度：如果实际达到每秒 100 步，1500 万步约需 42 小时；每秒 300 步则约 14 小时，另计评估和预实验。这是换算示例，具体耗时缺少你的硬件和实测速度。

评估规则从第一周就固定：

- 每 2 万训练步评估 20 个回合；最终每个模型评估 100 个回合。验证环境种子用 `10000–10019`，最终测试用 `20000–20099`，各方法共享相同测试场景。
- 主结果报告固定训练预算结束时的模型；验证集最优模型作为补充。测试集不参与调参或选模型。
- 报告三次训练的均值和标准差；成功率取回合最后一步的 `is_success`，同时记录最终距离、训练步数和实际耗时。

不要把密集奖励与稀疏奖励的累计回报直接排大小；跨奖励设定统一比较成功率和距离。PPO可能因完整采样批次而略超预算，图表记录实际交互步数。

另一个关键细节：FetchPush 到 50 步属于时间截断，不能随意当作任务真正终止；HER也需要完整回合数据。保持框架对时间截断的处理，检查保存和加载是否包含继续训练所需的经验回放。[环境结束规则](https://robotics.farama.org/envs/fetch/push/)、[HER 时间截断处理](https://stable-baselines3.readthedocs.io/en/master/modules/her.html)

**7．最终交付怎样才像一个完整项目**

交付集中在三件东西上：

- **可复现仓库**：安装说明、五组配置、训练与评估入口、版本记录、模型加载方式，以及清楚的上游引用。别人应能运行一个短实验，并复用你的评估程序。
- **三张核心图和一张结果表**：A–D 的成功率随训练步数变化；A、B 的成功率随实际耗时变化；D、E 的增益鲁棒性曲线；结果表列出三种子成功率、最终距离、耗时。
- **一份 4–6 页报告和约 90 秒视频**：报告解释任务、算法选择、对照关系、结果及局限；视频包含正常成功、误差下成功和失败案例，并标明方法、增益与最终距离。

失败案例重点分为“未接触物体、推错方向、推过目标”三类，结合轨迹解释。比如累计奖励变好、最终成功率却没变，可能说明策略只是把物体推近了，没有完成精确到位；这种分析比单放一个成功视频更能体现理解。

**8．面试时你应当能讲清什么**

你需要围绕项目回答三个层次的问题：

| 面试追问 | 你应当能给出的回答 |
|---|---|
| 为什么选 SAC，又为什么比较 PPO？ | 任务是连续动作控制；SAC可以重复利用历史交互数据，PPO是常见的策略梯度对照。最终效率差异由相同任务和预算下的实验支撑。 |
| HER到底改变了什么？ | 修改回放样本的目标，并重算奖励，物理轨迹没有变化；能解释为什么失败经历仍可能包含有用信息，也能指出它不能保证解决所有探索困难。 |
| 你具体完成了什么？ | 设计单因素对照、实现控制误差模块和独立评估、完成多种子实验、分析失败；明确区分自己实现的部分与使用的算法库。 |

此外，要能沿着代码讲出 SAC 的一次更新：**采样历史经验 → 计算目标 Q 值 → 更新两个 Q 网络 → 更新策略 → 更新熵系数与目标网络**；能解释 PPO为什么限制更新幅度、时间截断为什么影响价值估计。做到这里，这个项目才真正承接了 CS285 的学习。
